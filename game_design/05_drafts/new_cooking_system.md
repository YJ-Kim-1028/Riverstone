# 레스토랑 조리 시스템 기획 정리

## 1. 반드시 유지해야 하는 핵심 원칙 (변경 불가)

이 4가지는 어떤 방향으로 확장하든 절대 훼손하면 안 되는 시스템의 근간.

1. **NPC는 주문하지 않는다.** NPC가 원하는 메뉴를 말해주는 순간, 플레이어가 취향을 발견하는 재미가 사라짐.
2. **NPC 취향은 플레이어가 직접 발견한다.** 여러 음식을 만들어 먹여보며 "이 NPC는 이걸 좋아하는구나"를 알아내는 것이 핵심 콘텐츠.
3. **레시피도 플레이어가 직접 발견한다.** 처음부터 레시피를 쥐어주지 않고, 재료 조합을 시도해서 찾아내야 함.
4. **요리는 기본적으로 재료 2개로 구성된다.**

## 2. 기존 시스템의 문제

현재는 요리 UI를 열고 재료 슬롯 2칸에 재료를 선택하면 요리가 완성되는 구조. 재료 2개 조합이라는 규칙은 잘 전달되지만, 이 과정 자체가 클릭 한두 번으로 끝나는 순간적 결정이라 콘텐츠로서 얕음. 손에 익으면 하루 방문 NPC를 매우 빠르게 처리하게 되고, 레스토랑이 핵심 콘텐츠 중 하나임에도 금방 반복작업처럼 느껴짐.

## 3. 확정된 새 구조

### 3.1 재료와 조리기구

- 플레이어는 인벤토리에 있는 재료를 사용하여 요리할 수 있음.
- 주방에는 여러 종류의 조리기구(프라이팬, 냄비, 찜기 등)가 있음.
- **재료마다 사용 가능한 조리기구가 정해져 있음** (예: 감자는 찜기만 가능, 냄비 불가). 기본적으로는 재료:기구를 1:1로 고정.
- 각 조리기구는 1개만 배치.

### 3.2 조리 → 합치기 흐름

- 요리 하나가 재료 A + 재료 B로 만들어진다면, 두 재료는 **각자 맞는 조리기구에서 따로 조리**됨.
  - 예: 생선(프라이팬) + 감자(냄비) → 각각 조리 후 결합.
- 조리가 끝난 두 결과물은 별도의 **완성대/플레이팅 공간**(슬롯 2칸)에 넣어서 결합.
  - 올바른 재료 조합 + 올바른 조리법 조합 → 새 레시피 발견.
  - 잘못된 조합이거나 조리법이 틀렸다면 → 기존에 기획된 "괴상한 요리"가 나오는 이스터에그 처리.
- 완성대의 슬롯 2칸이 "재료 2개 조합 규칙"을 학습시키는 역할을 그대로 이어받음 (기존엔 냄비 슬롯 2칸이 하던 역할).

### 3.3 조리기구 상호작용 방식 (확정)

- 플레이어가 조리기구에 다가가 상호작용(E키/클릭)하면, **그 기구에서 사용 가능한 재료 목록을 플레이어의 전체 인벤토리 기준으로 보여줌.**
  - 목록에서 조리 불가능한 재료는 disabled 처리.
- 채택 이유: 조리기구는 이미 위치와 대상이 고정된 상호작용이라 기구 쪽이 사용 가능한 재료를 알려주는 방식이 더 자연스러움.
- 조리에는 실제 소요 시간이 있다(예: 감자 15초) — **실제 시간 기준**(인게임 시간 아님). 진행 상황은 진행바로 표시.
- 재료를 넣었던 것과 같은 상호작용으로, 조리가 끝나면 같은 슬롯에서 "조리된 재료"를 꺼내 인벤토리로 가져간다. 조리된 재료는 원재료와 별개의 새 아이템으로 취급(인벤토리 아이템 종류 확장 필요).

## 3.4 완성/서빙 = 식탁 통합 (확정)

- 별도의 "완성대"는 두지 않는다. **각 식탁(자리) 자체가 완성 지점**이다.
- NPC가 자리에 앉으면 그 앞에 빈 접시가 하나 생긴다.
- 플레이어는 조리된 재료 2개를 그 접시에 직접 넣어서 완성 = 즉시 서빙된다.
- 이 구조를 택한 이유:
  - "완성된 요리"가 별도의 인벤토리 아이템으로 존재하지 않게 되어, 미리 만들어 쌓아두는(사재기) 것이 구조적으로 불가능해진다.
  - "완성된 요리를 들고 가서 서빙 대상을 고르는" 별도 UI가 필요 없다 (접시 = 그 손님 것이 이미 정해져 있음).

## 3.5 쥐약(독) 처리 (확정 — 현행 시스템 유지)

- 완성 단계(접시에서 재료 2개를 합치는 순간)에서, 지금 `cooking_screen.gd`에 이미 구현되어 있는 **"쥐약 토글 + 확인 팝업" 패턴을 그대로 재사용**한다.
- 새로운 "인벤토리에서 아이템을 손에 들고 상호작용" 같은 시스템은 만들지 않는다 (검토했으나, 그런 "현재 든 아이템" 개념 자체가 프로젝트에 아직 없고, 새로 만들어도 발견성이 떨어질 우려가 있어 기각).
- 되돌릴 수 없는 행동이므로, 기존과 동일하게 확인 팝업으로 오조작을 막는다.

## 3.6 재료 사재기에 대한 입장 (확정)

- 조리 시간(초 단위, 실제 시간)이 손님의 식사 시간(30분, 게임 시간)보다 훨씬 짧기 때문에, 손님이 한 명만 있어도 이후 손님들 몫까지 미리 조리해두는 것을 원칙적으로 막을 수 없다는 데 합의함.
- 완전 차단은 포기하고, **"레스토랑 영업 중일 때만 조리기구 사용 가능"** 정도의 느슨한 제약만 건다.
- 완성 요리 자체는 3.4의 식탁 통합 구조 덕분에 사재기가 불가능하므로, 이 정도 제약으로 충분하다고 판단.
- 미니게임은 현재는 넣지 않는다 — 재료를 넣고, 기다리고, 꺼내고, 접시로 가져가 합치는 것으로 조리 루프가 끝난다.
