# Day 13 개발 현황 정리

`day12.md`에 이어지는 문서. NPC 대사/이메일 마무리 → 이메일 발송 로직 재설계 → 공포 시스템 전체(스토커/사칭 메일, 세이지 경고, 살인 발견 씬, 알리바이, 상점 잠금) → 플레이 중 발견된 버그 다수 수정까지 진행. NPC 콘텐츠 축(day9~13)과 공포 시스템 1차 구현이 이 세션으로 사실상 종결.

## 1. NPC 대사/이메일 마무리

- 라마/모카/마린/마르/우디/세이지/셰퍼드 이메일 채움. 로시/어셔 대사+이메일도 완료. 13명 전원 `dialogue.daily` 완비.
- **근본 버그 수정**: "좋아하는 재료 서빙" 판정이 요리 이름과 원재료 이름을 직접 비교해서 항상 실패하던 것 → `base_material` 필드 추가, `get_food_preference_for_ingredients()`로 재작성.
- `EmailManager`에 `requires_favorite_food`(실제 선호 요리 받은 날만), `affection_<N>_reached`(임계값 이벤트 완료 시 범용 트리거) 두 예외 추가 - 스키마 규칙과 매번 충돌 가능성 있어 사용자 확인 거쳐 진행.
- 셰퍼드 `affection_100_reached`에 모카 불륜 자백 이메일 신설.
- 세이지: 러브라인 삭제, 무당 어투로 전면 재작성, "..." 남발 정리, 칸당 2개로 밀도 축소(다른 NPC와 다른 예외).
- 어셔: 스토커 본인이라 결핍 서사 배제, 자기 소설 9편(책 도감) 소재로 활용, 호러 경계선 엄수.
- 남겨두기로 확정한 것: 마르 이메일 greeting 0개, 우디 gift_thanks 1개 - 사용자 확인, 의도적으로 안 채움.

## 2. 이메일 자동발송 로직 재설계

- gift_thanks/event_invite: 호감도 무관, 실제 행동 반응이라 그대로.
- greeting: 호감도 80+ 후보, 같은 NPC 7일 쿨다운, 하루 최대 2명만 발송(랜덤 확률 방식 폐기).

## 3. 플레이어 메일 언급 대사 (`dialogue.mail_reaction`)

- 메일 보내면 다음 대화에 `{player_mail_content}` 치환된 반응이 한 번 섞여 나옴. 13명 전원 반응 장치를 다르게 작성(통일 금지 - 사용자 지적).

## 4. 공포 시스템 구현

`data/horror/README.md` 확인 결과 백엔드(살인 조건/알리바이/엔딩 3종/노크·경고·사칭메일 트리거)는 이미 다 있었고 "신호 받아서 화면에 보여주는" 부분만 없었음 - 이번 세션에 대부분 연결.

- **상점 승계**: 이미 `shop.md`+`shop_manager.gd`에 구현되어 있던 걸 발견(벨제/셰퍼드, 마린/로시 - 한쪽 죽으면 남은 쪽이 승계, 둘 다 죽어야 온라인 전환). 그대로 유지.
- **초상화 흑백**: 런타임 셰이더(`scripts/shaders/grayscale_portrait.gdshader`)로 새 그림 없이 처리.
- **노크 소리**: 첫 살인 이후 밤 30% 확률, 3연타 재생.
- **레스토랑 액자**: (15,2) 타일에 오버레이, 살인 1건당 1회만 빨갛게 튀김("입장마다"는 사용자가 반려).
- **사칭 이메일**: `impersonation_emails.json`을 `default` 공용 문구 하나로 통일, `{victim_name}` 치환.
- **스토커 이메일**: 실제 발송 로직 자체가 없어서 신규 구현(3일 간격, early→mid→late 순차, 살인 건수로 상한). 초반 톤은 세 번 시행착오 끝에 "정보 비대칭이 플레이어에게 미치는 심리적 지배력을 즐기는 사이코패스"로 확정(불안한 짝사랑 아님). 사용자가 mid/late 내용을 직접 강도 높게 재작성.
- **세이지 경고**: `sage.json`의 `murder_warning_examples`(사용자 작성)를 하루 1회 최우선 강제 표시. `post_first_murder_soul_sight`/`player_poisoned_innocent_npc` 트리거도 연결(내용도 사용자 작성).
- **알리바이 시스템**: 살인 후 5일 이내 처음 만나는 NPC 첫 대사가 1인칭 알리바이 진술로 강제 삽입(1회성).
- **상점 잠금**: "NPC맵=NPC가게" 해석으로, 승계 로직상 "online"(전원 사망) 상태면 맵 입장 자체를 막음.
- **살인 발견 씬**: 비명 → 현재 맵에서 plaza3까지 실제로 뛰어감(`player.walk_to()`, 경로표 `MURDER_RUN_CHAIN`) → 폴리 옆까지 이동 → 강제 대화(`poli.json`의 `story_dialogue.murder_discovery`, 사용자가 직접 작성) → 페이드로 마무리. 폴리는 분신 스프라이트로 대체 배치, 나머지 NPC는 전원 숨김. 자루 그림은 안 그리고 대사로만 암시(공포 연출 원칙), 나중에 그리면 `assets/npc/poli_murder_sack.png`로 자동 배치되게 미리 연결.
- **미착수**: 이메일함 UI 연출(5종 중 1개), 엔딩 3종 컷신(방향 미정, 오늘 만든 툴킷 재사용 가능).

## 5. 플레이 테스트로 발견한 버그 (전부 수정 완료)

- `player.walk_to()`가 직선 이동이라 오브젝트에 걸림 → `WorldMap.find_path()`로 교체.
- 호감도 마일스톤 대사가 아예 연결 안 돼있어서 추억의 물건이 대사 없이 바로 지급됨 → 대사 표시 시점에 지급하도록 수정(`NPCManager._pending_milestone`).
- NPC 사망 시 파트너가 스케줄은 안 이어받아서 가게에 아무도 없는데 이용은 되던 문제 → 파트너 사망 시 그 스케줄을 조건부로 이어받게 수정.
- 살인 씬 중 응답 없음(hang) → 스크립트 이동 중 "워프 자동 전환" 로직이 동시에 발동해서 충돌한 게 원인, `_murder_scene_active` 플래그로 분리.
- 자양강장제 구매 실패 → 버그 아니고 디버그 테스트로 인벤토리가 가득 찬 것.
