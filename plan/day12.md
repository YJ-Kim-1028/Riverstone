# Day 12 개발 현황 정리

`day11.md`에 이어지는 문서. 이번 세션은 day11에서 "ChatGPT 외주로 반영 완료"라고 기록됐던 NPC 잡담 대사가 실제로는 너무 얇아서(요일당 1개씩뿐, 결핍/서사 없음), 이걸 훨씬 깊은 버전으로 한 명씩 다시 쓰는 작업이 메인이었다. 폴리 → 벨제 → 플로라 → 이샤 → 라마 → 마린 → 마르 → 모카 순으로 8명을 새로 썼고, 그 과정에서 대사 작성 원칙이 여러 번 더 다듬어졌다. 그 외 엔진 레벨 변경(초상화 기본 감정, 첫날 환영 메일, NPC→플레이어 선물 지급 매커니즘)도 있었다.

## 1. 이번 세션에 완료된 것

### NPC 잡담 대사(`dialogue.daily`) 심화 재작성 - 8명 완료

**완료**: 폴리, 벨제, 플로라, 이샤, 라마, 마린, 마르, 모카

- 요일(월~일) x 호감도(low/mid/high) 21칸 전부 최소 3개 이상 채우는 걸 기준으로 삼음. **단, 이샤(목-high 2개)와 폴리(금-mid 2개)는 각각 딱 한 칸씩 기준 미달로 남아있음 - 다음 세션에 마저 채울 것.**
- 핵심 글쓰기 원칙(`data/npc/README.md`에 문서화됨):
  - 감정을 직접 선언하지 않고 구체적 사건/관찰로 보여주기(예: "나는 외로워" 대신 구체적 에피소드).
  - 호감도가 오를수록 캐릭터의 "결핍"이 관찰→과잉해석→자기합리화/후퇴 구조로 드러나야 함.
  - **이번 세션에 새로 걸린 규칙**: `dialogue.daily`의 한 요일x호감도 칸 안에 있는 여러 항목(entry)은 매번 그중 하나만 랜덤으로 뽑힌다 - 즉 서로 다른 항목끼리는 절대 "이어지는 이야기"로 설계하면 안 됨(한 항목 안의 여러 줄은 한 번에 같이 보여지므로 괜찮음). 모카 화요일/목요일 high에서 이 실수가 두 번 반복되다 사용자에게 지적당해 수정함 - `feedback_npc_dialogue_writing_standard.md`에 기록.
  - 마을에 없는 가게/설정 발명 금지, 다른 NPC의 이미 확정된 성격과 모순되는 묘사 금지, 첫 살인 전 공포 요소 암시 절대 금지(마르의 쥐약 관련 잡담을 전부 들어낸 사례 등).
  - 이메일은 "편지니까 이 말 하는 거야"류 자기변명 문구 금지, 구어체 잡담과 톤을 구분할 것.
- 초상화 감정 기본값을 `happy`→`default`(무표정)로 바꾼 뒤(`dialogue_screen.gd`), 기쁜 대사만 사용자가 직접 지정한 줄에 한해 `"emotion":"happy"`를 명시 태깅하는 방식으로 정리. 폴리/벨제/플로라는 한 차례 과태깅(거의 모든 줄에 happy를 넣어버림) 사고가 있었고, 사용자가 직접 정리하기로 함 - **폴리 파일의 happy 태그 상태는 사용자가 알아서 정리 중이라 손대지 않았음.**

### 모카(`mocha.json`) - 이번 세션 마지막 작업, 특히 반복 수정 많았음

- 다이얼로그 21칸 전부 채움 + 유효성 검증(JSON parse, 3개 이상, 중복 없음)을 매 수정마다 Node 스크립트로 확인.
- **버그 수정**: 사용자가 직접 편집하다가 생긴 JSON 문법 깨짐(괄호 메모가 따옴표 밖에 붙어있던 것) 발견 후 수정.
- **캐릭터 설정 오류 수정**: 셰퍼드(20대)를 "나이가 있어서 편하다"고 묘사한 대사가 완전히 거꾸로였음(모카가 40대로 더 연상) - `shepherd.json`의 mother-complex 설정에 맞게 "나보다 한참 어린데도 기대려 한다"로 수정.
- **놓쳤던 설정 반영**: 모카의 전남편은 단순 "바람핀 전남편"이 아니라, `poli.json`/`game_design/03_npcs/poli.md`·`flora.md`에 이미 확정된 대로 **플로라를 스토킹하다 체포 직전 폴리에게 정당방위로 사살당한 인물**. `poli.json`에 이미 있던 "모카가 요즘 나한테 인사를 유독 자주 하는 것 같다"(화-mid)에 대응하는 내용이 모카 쪽엔 전혀 없었던 것도 이번에 발견 - 토-mid에 폴리 언급(라떼 취향 - 폴리 파일과 교차 일치) 한 줄만 추가하고, "이유 모르게 유독 잘해준다"는 식의 추가 떡밥성 대사는 사용자가 "이상하다"고 판단해 들어냄. **폴리↔모카 관계는 아직 더 다듬을 여지가 있음, 다음에 이어갈 것.**
- `game_design/03_npcs/mocha.md`에 이미 확정돼 있던 원문 대사("웃기지, 다시는 사랑 같은 거 안 할 줄 알았는데" / "누군가한테 미안한 일이라는 거 알아... 사람은 가끔 자길 위해서 나쁜 짓도 하고 사는 거 아닐까" - 원래 "벨제가 불쌍한 건 알아"로 벨제를 직접 언급했으나 사용자 요청으로 일반화)를 셰퍼드 관련 high 대사로 그대로 편입.
- 플로라(`flora.json` 일-low)가 이미 "모카 카페에 딸기라떼 추가해줬으면"이라고 언급한 것에 대응해 목-low에 모카 쪽 반응 대사 추가(딸기라떼를 실제로 메뉴화하지는 않음 - 없는 기능 암시 방지).

### NPC → 플레이어 선물 지급 매커니즘 신규 구현

- `special_notes`에 "호감도가 일정 수치 이상이면 커피를 선물한다"고 적혀만 있고 실제 코드가 없던 것을 발견, 처음엔 `affection_events`(호감도 임계값) 방식으로 만들었다가, 사용자가 "호감도 기준이 아니라 **그 대사가 실제로 나왔을 때** 선물이 되어야 한다"고 정정.
- 최종 구조: `dialogue.daily`의 대사 줄 배열 안에 `{"type":"gift","item_id":"..."}` 객체를 끼워 넣으면(기존 `{"type":"choice"}` 패턴과 동일), 그 줄이 실제로 화면에 뜨는 순간 조용히 아이템이 지급되고 다음 줄로 자동으로 넘어감. 랜덤 대사풀이라 이 항목이 뽑힐 때마다 매번 지급됨(1회성 아님).
- 구현: `dialogue_screen.gd`(`GIFT_TYPE` 처리) → `NPCManager.grant_gift_item()`(신규 공개 함수, `npc_gift_item_triggered` 신호 emit) → `InventoryManager`/`AudioManager`가 신호 받아서 아이템 지급 + 습득 사운드 재생. `memento_received`/`_on_memento_received`와 동일한 배선 패턴을 그대로 따름.
- 모카의 수요일 mid 대사를 buff_item 원문("오늘은 좀 바빠 보이네. 이거 마시고 다녀.")으로 바꾸고 이 트리거를 붙임 - 다른 NPC도 같은 방식(`"type":"gift","item_id":"..."`)으로 재사용 가능한 범용 구조.
- `data/npc/README.md`에 `gift` 타입 사용법 문서화 완료.

### 그 외 엔진/UI 변경

- **초상화 감정 기본값 변경**: `dialogue_screen.gd`의 `DEFAULT_EMOTION`을 `"happy"`→`"default"`로 변경 - 이제 명시적으로 `"emotion":"happy"` 태그된 줄만 웃는 얼굴이 나오고, 나머지는 전부 무표정이 기본. 전체 NPC 초상화 렌더링에 영향을 주는 엔진 레벨 변경.
- **첫날 환영 메일 시스템 신규**: `story_progress.player_arrival` 트리거 추가 - 새 게임 시작(캐릭터 생성 확정) 시 `EmailManager.send_arrival_emails()`가 전 NPC를 순회하며 환영 메일을 발송(`title_screen.gd`의 `_on_character_confirmed()`에서 호출). 폴리는 나이가 있어 이샤/플로라의 도움을 받아 작성했다는 설정으로 처리.
- **`{player_name}` 치환을 메일 상세화면에도 추가**: `mail_detail_panel.gd`에 `GameManager.player_name` 치환 로직 추가 - 기존엔 대화창(`dialogue_screen.gd`)에만 있었음.
