## 5. 대사/대화 시스템 - day10 세션 결정 사항

- **감정 태그 대사 형식 확정 및 구현 완료.** `dialogue.daily` 등 `lines` 계열 배열의 원소는 문자열(감정 기본값 `happy`) 또는 `{"text","emotion"}` 딕셔너리(감정 지정, `happy`/`sad`/`angry`/`default` 중 하나) 둘 다 허용. 상세 규칙과 예시는 `data/npc/README.md`, 구현은 `scripts/ui/dialogue_screen.gd` 참고.
- **선택지 있는 일상 대화 구현 완료.** `{"type":"choice","options":[{"label","affection","response"}]}` 형태로 `dialogue.daily`에 넣으면 대화 중 플레이어가 ▲▼/E로 고를 수 있고, 고른 옵션의 `affection` 값이 즉시 호감도에 반영된 뒤 `response` 줄이 이어서 나옴. 사용자 지시: "선택과 결과"가 실제로 체감되게(연출용 아님), 우선 일상 잡담부터 적용. `NPCManager.apply_dialogue_choice()` 추가.
- **NPC 캐릭터성 강화 방향 논의 중 (미착수).** 사용자가 "NPC별 성격/관계를 디테일하게 채우고, 플레이어가 결핍·동질감을 느끼게 하는 게 중요하다"는 방향 제시.
  - (제안, 미확정) 각 NPC 문서에 "핵심 결핍" 한 줄 요약 추가 — 기존 `스토리`/`설계 목표` 내용을 근거로 뽑아내는 것. `game_design/`은 읽기 전용 규칙이라 사용자 승인 필요.
  - **`data/npc/*.json`에 `hobbies`/`talk_topics` 필드 추가 예정 - 아직 미착수, 주제 승인 대기 중.** 사용자 요청: 먼저 후보 주제를 공유받고 승인한 뒤에 실제로 필드를 채워달라고 함.
    - talk_topics 카테고리 후보로 심리학적 근거 6가지 제시함: 자기개방 이론(Social Penetration Theory), 프랫폴 효과(Pratfall Effect), 유사성-호감 효과(Similarity-Attraction Effect), 반응성 지각(Perceived Partner Responsiveness), 보편적 결핍 테마, 단순노출 효과(Mere Exposure Effect). 다음 세션 시작 시 사용자가 이 중 채택할 축을 먼저 확인할 것.
    - 채택되면 `talk_topics` 항목마다 어떤 축을 노리는지 `category` 값으로 표시할지도 같이 확정 필요.
- **"반응성 지각" 축(선물 받은 후 반응 등 트리거 대사) - 설계만 논의, 구현은 아직.** `rain_conversation`/`horror_conversation`과 같은 패턴(조건부 추가 풀)으로 `dialogue.gift_thanks_conversation` + `NPCManager.has_recent_gift()`를 만들면 된다는 방향까지만 정함 - 실제 구현은 다음 세션.
- **플로라 `dialogue.daily`/`rain_conversation` 실제 대사로 채움 완료 (요일그룹×티어당 low 6 / mid 5 / high 4, rain 4개, 총 49개 항목).** 1차 초안은 사용자 피드백으로 전면 재작성함 - "심리 원리를 그대로 설명하는 문장"이라 캐릭터 구분 없이 밋밋했던 문제. 재작성 기준: 감정을 직접 선언하지 않고 구체적 사건/사물로 보여주기(플레이어의 레스토랑 요리, 그녀가 파는 상추, 어셔의 실제 책 제목 등 기존 데이터와 연결), 그녀만의 말버릇("~그치?" 확인받고 싶어하는 성향 반영), `{player_name}` 자리표시자로 플레이어를 직접 호명. **앞으로 다른 12명도 이 기준(구체적 사건 기반, 게임 상태 연결, 캐릭터별 말버릇)으로 써야 함 - 1차 초안 같은 추상적 문장 반복 금지.**
- **`{player_name}` 자리표시자 구현 완료.** `dialogue_screen.gd`가 대사 표시 시 `GameManager.player_name`으로 치환. `data/npc/README.md`에 문서화.
- **역할 분담 결정: 대사 실제 문장은 사용자가 직접 쓴다.** 2차 재작성도 "오글거린다"는 피드백 - AI가 쓰는 감성 대사 특유의 어색함(모든 줄이 의미를 담으려 함, 부자연스러운 리듬)이 근본 원인으로 판단됨. Claude는 상황/소재 뼈대(스켈레톤)만 제공하고, 실제 대사 문장은 사용자가 직접 작성하는 것으로 방향 전환. 플로라 `dialogue.daily`/`rain_conversation`은 다시 빈 배열로 되돌림(`data/npc/flora.json`). 플로라용 뼈대(49개 슬롯의 상황 요약)는 아래 참고.
