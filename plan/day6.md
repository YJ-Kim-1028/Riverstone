### 1-2. 낚시 UX 반복 수정 (실제 플레이 피드백 기반)
- 디버그 시작 아이템: 모자/신발 테스트 아이템 대신 낚싯대 자동 지급(F8, 부팅 시)으로 교체
- 드래그 미리보기 아이콘이 커서에서 벗어나 보이던 버그 수정 - 미리보기 노드에 원본 아이콘과 같은 `expand_mode`/`stretch_mode`/`size`를 안 맞춰서 실제 그려지는 크기가 의도(12x12)보다 컸던 게 원인(`inventory_slot.gd`, 인벤토리/장비/조리기구/완성대 등 드래그 쓰는 모든 화면에 공통 적용)
- 장비 슬롯 순서: 모자-신발-손 → 모자-손-신발(사용자 지시)
- 물고기 스폰 지점이 전부 같은 y좌표 한 줄에만 있던 버그 → 위/아래 지그재그 배치로 수정
- 난이도: 물고기 노출 시간 0.9초 → 0.5초로 단축
- 포획 성공 후에도 물고기가 다시 뜨던 버그 수정 - 겉모습만 숨기고 내부 사이클을 안 멈춰서, 남은 사이클이 나중에 다시 살아났던 것(`FishingFish.stop_cycle()` 신규)
- 스폰 지점이 창 밖으로 살짝 잘리던 버그 수정(좌표 재배치)
- 실제 그림 연결: `frame_fishing.png`(배경, 48x48 9-slice), `icon_fish.png`(물고기 아이콘) - 기존 placeholder(파란 원/재사용 프레임) 대체
- 성공 표시를 "~를 낚았다!!" 텍스트에서 잡은 물고기 아이콘 + "획득!"으로 변경, 실패 문구는 "놓쳤다..." → "실패"로 변경
- 낚시창 X 닫기 버튼 제거 - 시간 지나면 자동으로 닫히고 ESC로도 닫히므로 불필요(사용자 지시, `collection_screen.gd`와 같은 "닫기 버튼 없이 ESC 전용" 방식으로 통일)

### 1-3. 오디오 시스템 확장
- **파도 소리**: `sfx_plaza345_wave.mp3` 신규 - 바다가 있는 맵(plaza3/4/5)에 있을 때 날씨/실내 여부와 무관하게 재생, 브금/비보다 조용한 배경음 레벨
- **강/연못 소리**: `sfx_pond.mp3` 신규 - 처음엔 맵별 y좌표를 손으로 맞추는 방식으로 만들었다가, 사용자 요청으로 실제 Water/Pond 타일까지의 거리 기반으로 전면 개선(`WorldMap.get_distance_to_nearest_pond()` 신규 - Pond 레이어만 보고 Water(바다)는 일부러 제외해서 파도 소리랑 안 겹치게 함). plaza1/2에서 강에 가까이 갈수록 볼륨이 커짐
- **빗소리**: `sfx_rain2.wav`로 교체(기존 `sfx_rain.mp3`보다 낫다고 판단, 사용자 확정). 볼륨은 30%→40%→0%(원복, 너무 안 들려서) 순으로 조정, 최종 0%(감쇠 없음)
- **브금 볼륨**: 0%→30%↓→45%↓→60%↓→45%↓(다른 소리 대비 너무 작아서 한 단계 되돌림) 순으로 반복 조정, 최종 **-45%**(-5.2dB)
- `rain_drop.png`(비 이펙트 그림) 색상 변경 후 재임포트

### 1-4. 플레이어 임시 스프라이트
- 플레이어 전용 스프라이트가 없어서(게임 완성 후로 미뤄둔 항목) NPC 어셔(usher)의 스프라이트를 임시로 재사용(사용자 지시 - 낚싯대 든 모습 등을 확인해보고 싶어서). `player.tscn`에 `Sprite2D` 추가, `player.gd`에 `npc_sprite.gd`와 동일한 프레임 규칙(16x32, 4방향 정지/걷기)으로 애니메이션 구현. 기존 `_draw()` 색깔 사각형 placeholder는 제거
- 장비 탭의 작은 "플레이어 미리보기"(`player_preview.gd`)도 같은 상수를 참조하도록 연동 - 나중에 진짜 스프라이트로 바뀌면 `player.gd`만 고치면 둘 다 따라감
- **대각선 이동 시 이상한 방향이 나오던 버그 발견/수정**: 방향키를 "누른 순서"로 추적하던 방식이라 대각선 이동이나 반대 키 동시 입력(W+S) 시 실제 이동과 안 맞는 포즈가 나왔음 → NPC 스프라이트가 이미 쓰던 방식(실제 이동 벡터의 우세한 축으로 판정)으로 교체(`_direction_from_vector` 신규)

## 2. 시도했다가 포기한 것 - 물결 애니메이션

`game_design/04_locations/01_overview.md`의 "Water/Pond 레이어 - 물결 효과 적용 필요" TODO를 시도했다.

1. UV를 흔드는 위치 이동(일렁임) - 진폭을 낮춰도 어지럽다는 피드백
2. 물 전체 밝기를 오르내리는 펄스 - 타일마다 로컬 UV가 따로 놀아서 타일 경계가 네모나게 도드라짐
3. 물 그림 속 흰 반짝임 점만 깜빡이기(색상 기반 판정, 사용자가 준 `#81c9b1` 기준) - 효과가 거의 안 보이는데 렉만 발생

**포기한 이유(구조적)**: 이 프로젝트는 타일 하나하나가 전부 개별 `Sprite2D` 노드로 그려지는 구조(`home_map.gd`, 내장 TileMap 미사용)라, 타일마다 셰이더 재질을 달면 Godot의 자동 배칭이 깨져서 타일 수만큼 렉이 늘어난다. 효과 자체를 손봐서 해결될 문제가 아니어서 전부 원복(관련 코드/셰이더 파일 삭제).

**왜 내장 TileMap을 안 썼는지 논의**: Tiled로 맵을 만든 것과는 무관하고(Tiled+내장 TileMap 조합은 흔한 정상 조합), `home_map.gd`가 `.tmx`를 직접 파싱해서 타일마다 수동으로 Sprite2D를 만드는 커스텀 방식을 선택한 게 원인. 내장 TileMap도 Y-정렬(`y_sort_enabled`, 타일별 Y-정렬 기준점)을 지원하므로 기능적으로 못 하는 건 아니고, 마이그레이션 비용(맵 로딩/충돌/Y-정렬/물 타일 감지 코드 재작성 + 기존 `YSortAnchor` 배치를 타일셋 기준점 설정으로 재작업)이 문제. **지금 당장 급한 문제는 아니라고 판단해서 보류** - 나중에 필요해지면(진짜 렉 체감되거나 물 애니메이션이 꼭 필요해질 때) 그때 계획을 다시 잡기로 함.
