# Day 19

day18 세션에서 이어짐 - 개발 작업이 아니라 홍보/포트폴리오 준비 세션. CLAUDE.md 정리, 디자인 캔버스 3종 제작, 그 과정에서 여러 차례 있었던 "실제로 누가 뭘 했는지" 정확성 교정이 세션의 대부분을 차지함.

## CLAUDE.md 정리

- "미구현 항목 (임의로 내용 생성 금지)" 섹션 삭제 - 도감 보상(영혼의 결정/부활), 스토커 사칭 이메일, 어셔 알리바이 증언, 세이지 경고 대사 전부 이미 구현/작성 완료된 상태였음을 실제 파일 확인으로 검증 후 삭제. 오래된 메모가 방치되어 있었던 것.
- 9번째 줄 "(보상 미정)" 문구를 실제 구현(추억의 물건 전체 수집 + 엔딩 하나 달성 시 영혼의 결정 지급 → 신사 제단에서 부활)에 맞게 수정.

## 디자인 캔버스 3종 제작 (Claude Design 스킬 사용)

1. **게임 회사 제출용 포트폴리오** - https://claude.ai/code/artifact/932d715d-bd52-4c74-80e9-bf0dff93312c
2. **일반 개발자 제출용 케이스 스터디** - https://claude.ai/code/artifact/9767c62d-124a-47bd-b599-8d4687eebdc0
3. **예고편 촬영용 컷 리스트(스토리보드)** - https://claude.ai/code/artifact/2582779d-f9e9-486e-bb6e-adff8b2b7ec8

두 포트폴리오는 처음엔 하나의 방향(범용 마케팅 카드)으로 만들었다가, 사용자가 "게임 회사용/일반 개발자용을 나눠야 하지 않냐"고 지적해서 완전히 다른 두 문서로 재설계함. 레이아웃도 처음엔 좁은 세로 1칼럼(문서 스타일, `print: flow`)으로 만들었다가 "웹처럼 안 보인다"는 지적을 받아 넓은 웹 레이아웃(1200~1240px, 2~3단 그리드)으로, `expand: fill`을 안 줘서 뷰어가 레터박스로 축소 표시하던 것도 나중에 수정함.

## 기여도 정확성 교정 (세션의 핵심)

사용자가 "코드는 AI가 짰는데 포폴에 뭘 내 걸로 써야 할지 모르겠다"고 물어본 데서 시작해서, 여러 차례 구체적인 교정이 있었음:

- **잘못 짚은 것**: "헤드리스 자동화 하네스로 버그를 검증했다"는 걸 사용자 본인의 기술 기여처럼 말했다가, day18 로그를 다시 보고 그건 전혀 다른 얘기(엔딩 나레이션 밝기 오해를 검증한 것)였고 그것도 Claude가 지난 세션에 만든 것이었음을 정정.
- **확정한 것 (증거 기반)**: 코드 전체에서 `사용자 지시` 주석을 grep해 스크립트 54개 파일에 392건이 있음을 확인. 그중 구체적 수치/조건이 담긴 사례(이벤트 페이드 0.6→1.2초, NPC 접근거리 3→5칸 등)를 포트폴리오에 인용문+수치로 반영.
- **JSON 데이터 스키마 설계**는 사용자 본인 기여로 확정 (`data/npc/sage.json` 등 실제 구조 발췌해서 포폴에 근거로 넣음).
- **YSortAnchor 수동 배치**(Home.tmx/plaza2.tmx에 사용자가 직접 Tiled로 배치)는 발견했지만, 사용자 본인이 "라이브러리 기능 대신 손으로 그린 건 오히려 안 좋아 보인다"고 판단해서 포폴에서 제외.
- **성능 최적화(TileMapLayer 전환, 700ms→85ms)**: 처음엔 사용자가 기술적으로 주도한 것처럼 정리했다가, 실제로는 "체감 성능이 이상한 것 같다"고 사용자가 질문한 것에서 시작해 Claude가 원인 진단+해결책(TileMapLayer)을 제안한 것이었다고 사용자가 직접 정정. 이후 포폴에는 "사용자가 감지하고 질문 → 조사 결과 원인 확인 → 700ms→85ms 개선"이라는, 사용자의 QA 기여로 정확히 재분류해서 반영.
- 대사 총량(13명 NPC 전체 데이터에서 대사/이벤트/이메일 등 "줄" 단위 전수 카운트) = **2,709줄**. 다만 이 중 실제로 사용자가 직접 쓴 비율은 세션 로그상 애매함 (day10에 "AI가 쓴 감성 대사가 오글거려서 이후 사용자가 직접 쓰는 방식으로 전환"이라는 기록이 있지만, 그 뒤로도 "Claude가 전체 문장을 쓰되 기준을 더 엄격히" 같은 재반전 흔적도 있음 - 다음에 필요하면 더 파볼 것).

## 캐릭터/서사 설계 내용 정리 (게임 회사용 포폴에 반영)

- 성별 타겟 캐릭터 매트릭스: 여성 플레이어向(라마/셰퍼드/어셔/마르/마린/로시), 남성 플레이어向(세이지/플로라/벨제/이샤) - 각 한 줄 특징과 함께.
- 유대감 설계 근거 - 심리학 프레임 5가지(자기개방 이론/유사성-호감 효과/반응성 지각/프랫폴 효과/단순노출 효과)를 실제 설계 요소에 매핑. day10.md에 이미 기록되어 있던 6개 후보(자기개방/프랫폴/유사성-호감/반응성 지각/보편적 결핍/단순노출) 중 5개를 사용.
- `game_design/03_npcs/*.md` 13개 전체 + `02_horror/murder_system.md`, `stalker.md`, `horror_events.md`를 서브에이전트로 정독시켜서 "결핍→서사" 사례 5건(이샤/플로라/벨제/셰퍼드/마르)과 "추리 설계"(분명한 단서 vs 헷갈리는 요소) 목록을 원본 문서 근거로 재작성.
- **마르 캐릭터 관련 정정**: 사용자가 초기에 마르를 "플레이어에게 의존하는, 모성애를 자극하는 캐릭터"로 설명했는데, `marr.md` 원본에는 "마르는 우정이나 사랑 같은 감정을 이해하지 못한다"고 명시되어 있어 정면으로 충돌함을 발견. 사용자가 확인 후 해당 표현을 완전히 삭제하기로 결정 (대안으로 제시했던 "서투름이 보호본능을 자극한다"는 재포장도 사용자가 "그냥 사회성 떨어지는 거 아니냐"고 거부해서 폐기).
