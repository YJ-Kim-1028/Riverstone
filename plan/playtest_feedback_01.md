## 3번 관련 메모 — 현재 코드가 이미 갖춘 것

3번을 구현할 때 새로 만들 게 생각보다 적다. 지금 상태:

- **대화 풀은 이미 있다.** `data/npc/*.json`의 `dialogue.daily[요일][low|mid|high]`가
  요일·호감도 구간마다 대화를 3~4개씩 배열로 갖고 있다.
- **줄 단위 초상화 전환도 이미 된다.** 각 줄은 문자열이거나
  `{"text": "...", "emotion": "happy"}` 형태라, **한 번의 대화 안에서도 초상화가 바뀔 수 있다.**
- **풀 회전 로직도 이미 있다.** `npc_manager.gd:672` `get_daily_dialogue()`가 무작위로 뽑되
  직전에 나온 것(`_last_daily_dialogue_index`)은 피한다.
- **호감도 중복 상승 방지도 이미 있다.** `npc_manager.gd:197` `talk()`이 `has_talked_today()`로 막는다.

**막고 있는 건 딱 한 줄이다.** `npc_world_manager.gd:164`

```gdscript
if not ignore_talked_today and NPCManager.has_talked_today(npc_id):
    continue
```

오늘 이미 대화한 NPC를 "말 걸 수 있는 대상"에서 아예 빼버려서, 하루에 한 대화만 보게 된다.

→ 즉 **하루 대화 횟수 상한(3회 정도)만 두고 이 차단을 풀면** 나머지(풀 회전, 초상화 전환,
호감도 1회 제한)는 그대로 동작한다. 호감도는 `talk()`이 이미 막고 있어서 반복해도 안 오른다.

### 참고 — 스타듀밸리는 어떻게 하나

스듀는 **"여러 번 말 걸기"로 풀지 않는다.** NPC당 하루 대사는 원칙적으로 하나이고,
그날 이미 말을 걸었으면 다시 걸어도 짧은 반복 대사만 나온다.

대신 **한 번의 대화 안에서 초상화를 여러 번 바꾼다.** 대사 문자열에 토큰을 섞어 쓰는 방식이다.

- `$h` 기쁨, `$s` 슬픔, `$a` 화남, `$l` 애정, `$u` 특수, `$n` 중립 — 그 지점부터 초상화 교체
- `#$b#` — 페이지 넘김

그래서 대사 한 덩어리가 2~3장으로 넘어가면서 표정이 계속 바뀐다.

**이 프로젝트는 `emotion` 필드로 이미 같은 걸 할 수 있다.** 그러니 선택지가 둘이다.

1. 하루 대화 횟수를 3회로 늘린다 (친구가 요청한 방식, 코드 한 곳 수정)
2. 기존 대사에 `emotion`을 더 촘촘히 넣어 대화 한 번에 표정이 여러 번 바뀌게 한다 (스듀 방식, 데이터 작업)
3. 둘 다 한다

2번은 대사 데이터를 손대는 일이라 **어떤 대사에 어떤 표정을 넣을지는 사용자 확인 후 진행**해야 한다.
