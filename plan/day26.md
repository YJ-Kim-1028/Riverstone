  없었음 - 마르만 예외.

  확인 결과 문제없어서 그대로 둠. 구조/배열길이 검증 통과.

## HD 도구 사용 포즈 시스템 신규 구현

- **배경**: day24에서 발견한 갭 - HD 캐릭터 시스템(`player.gd
  ._update_hd_animation()`)은 옷마다 정지/걷기 프레임만 있고 도구 사용
  포즈가 아예 없었음("프로토타입 단계라 도구 포즈는 일단 무시" 주석).
- **시트 구조 확장**: 방향당 프레임 구성을 [정지 1 + 걷기 8]에서 [정지 1 +
  걷기 8 + 도구 포즈 1]로 확장(`HD_TOOL_FRAME_OFFSET`/`HD_GROUP_SIZE` 상수
  추가, `_hd_tool_index()` 함수 추가). 이 프레임 그리드는 헤어(11종)/눈
  (4종)/아웃핏(12종) 시트 전부가 공유하는 구조라, **26개 PNG 파일 전부**
  1152x64 → 1280x64로 폭을 늘렸음(PowerShell System.Drawing 스크립트,
  기존 파일은 프로젝트 관례대로 `_old.png`로 백업). 헤어/눈/아직 전용 그림이
  없는 아웃핏은 정지 프레임을 그대로 복제해서 새 칸을 채워 넣음(안전한
  플레이스홀더 - 시각적 변화 없음).
- **여러 차례 방향 전환(사용자와 논의)**:
  1. 처음엔 낚싯대 전용 포즈(낚싯대까지 그림에 포함, 아이콘 오버레이 없이)로
     시도 - PixelLab이 계속 낚싯대를 어깨 위로 뻣뻣하게 그려서(프롬프트를
     여러 번 수정해도 반복) 포기.
  2. **최종 결정**: 도구 종류 구분 없이 손을 낮게 모은 범용 포즈 하나만
     쓰고, 실제 도구 모양은 기존 아이콘 오버레이(Tools.png, 손 위치에 얹는
     방식)가 보여주는 걸로 단순화(사용자 지시 - "그냥 뭘 쥐고있는 포즈로만
     할거야", "손 모은거로"). `player_tool_overlay.gd`의 `get_tool_id()`
     접근자(중간에 도구별 분기용으로 추가했다가) 다시 삭제 - 안 씀.
  3. `player.gd._update_hd_animation()`: `tool_overlay.is_active()`면
     도구 종류 상관없이 새 포즈 프레임 + 기존 아이콘 오버레이
     `update_position()` 호출.
- **plain2 포즈 그림**: 사용자가 PixelLab으로 4방향 손 낮게 모은 포즈를
  직접 생성 → 프리뷰 파일(`preview_player_plain2.png`)에 저장 → 이 세션
  중 두 번 재크롭/삽입(중간에 프리뷰 내용이 바뀌었는데 실제 게임 시트
  `player_outfit_plain2.png`에 반영이 안 됐던 걸 "Godot 재임포트" 문제로
  착각한 적 있음 - 실제로는 그냥 크롭 재실행이 필요했던 것, 픽셀 diff로
  확인 후 재적용).
- **룩(look) 옷 진행상황**: 사용자가 직접 룩4까지 포즈 그림 작업 완료(본인이
  크롭까지 직접 하기로 함 - "1px이라도 안맞으면 이상하게 보여서 내가
  해야할거같은데"). **룩5~10은 다음 세션 몫.**
- **기본옷(plain, 룩1번) 선택 차단**: 사용자가 이 옷은 포즈를 도저히 못
  그리겠다고 판단(2026-09-16) - `shop_manager.gd`의
  `DEFAULT_UNLOCKED_HD_OUTFITS`에서 `"plain"` 제거(`["plain2"]`만 남김).
  `HD_OUTFITS` 배열 자체는 안 건드려서 이미 이 옷을 입고 있던 기존 세이브는
  그대로 렌더링되고, 캐릭터 생성/옷장 순환 목록에만 다시 안 뜨게 됨. 상점에도
  "outfit_plain" 판매 항목이 없어서 구매로도 못 얻음.
- **아이콘 오버레이 위치 미세조정**(`player_tool_overlay.gd`):
  - 좌/우(west/east) 방향 ICON_OFFSET y값: 사용자가 "낚싯대가 어깨 위로
    올라간다"고 인게임에서 확인 → -16 → -17 → -19로 두 차례 조정(사용자
    "방금 올린거의 2배는 더 올려야돼" 지시로 마지막 -19까지).
  - 물뿌리개 아이콘만 별도로 3px 아래로(사용자 지시 - "물뿌리개 아이콘만
    조금 내릴 수 있어? 다른 소총이나 괭이 낚시대는 그대로 두고") - 새 상수
    `TOOL_OFFSET_ADJUSTMENT`(도구별 위치 가산값) 신설, 앞으로 도구 하나만
    미세조정하고 싶을 때 이 패턴 재사용 가능.

## 버그 발견 및 수정: 황금 물뿌리개 사용 시 일반(파란) 아이콘이 나옴

- 사용자 리포트(2026-09-16) - "왜 황금 물뿌리개일때도 파란 물뿌리개가 나왕??":
  `main.gd`의 물주기 동작 코드가 실제 장착 아이템을 확인하지 않고
  `player.tool_overlay.start("watering_can", ...)`을 하드코딩하고 있었음.
  `EquipmentManager.get_equipped(EquipmentManager.HAND_SLOT)`을 그대로
  넘기도록 수정. `player_tool_overlay.gd`의 `MIRRORED_ICON_TOOLS`/
  `TOOL_OFFSET_ADJUSTMENT`에 `"golden_watering_can"`도 같이 등록(반전/위치
  조정이 일반 물뿌리개와 동일하게 적용되도록).

## 사냥 미니게임 - 3회 성공해야 포획되도록 변경

- 사용자 지시(2026-09-16) - "그 새랑 토끼 잡을때 나오는 미니게임... 3번
  성공해야지만 포획할수있게 변경안돼? 지금은 한번만 성공해도 바로 돼서":
  `hunting_manager.gd`에 fishing_manager.gd의 "필요 클릭 수 채우면 그때
  성공" 패턴을 그대로 이식.

  - 스위트스팟 명중 시 카운트만 올리고, 3번째에 도달해야 실제 포획(총소리+

    다음 판정용 스위트스팟 위치를 새로 뽑아서 조준을 이어감(같은 자리
