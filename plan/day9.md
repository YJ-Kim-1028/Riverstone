# Day 9 개발 현황 정리

`day8.md`에 이어지는 문서. 오늘은 세션이 특히 길고 범위가 넓었다 - 책(도감) 시스템, 아이템 우클릭 사용, 도감 툴팁 버그, 자유 배치형 보관 상자 시스템 전체, 그리고 세션 후반부 대부분을 차지한 타이틀 화면·캐릭터 생성 화면·캐릭터 색상 커스터마이징 시스템(여러 차례 재설계)까지 다뤘다. 마지막에는 "게임 시작 전인데 시간이 흐르고 있었다"는 치명적 버그도 발견해서 고쳤다.

## 1. 오늘 완료한 것

### 1-1. 책(도감) 시스템 신규
- `data/books/books.json` + `BookManager` + `book_screen` 신규 - 어셔의 서점에서 산 책을 우클릭하면 도감창과 같은 형식의 책 UI가 뜨고 내용을 읽을 수 있음
- 예시 1개만 채우고 나머지는 `data/books/README.md`에 TODO로 남김(기획 문서화 규칙 준수)
- 사용자 요청으로 단일 중앙 페이지 → 좌/우 양쪽 펼침 페이지 레이아웃으로 재작업, 글자 크기도 축소

### 1-2. 아이템 우클릭 "사용" 기능 완성
- 레시피 아이템(`recipe_random` 등)·커피·활력의 물약 등 소비 아이템 설명에는 "우클릭으로 사용"이라고 적혀있었는데 실제로는 동작 안 하던 문제 발견 → 인벤토리(`inventory_slot.gd`)와 TAB 장비 탭(`equipment_panel.gd`) 양쪽 다 우클릭-사용 배선
- 레거시였던 I키 인벤토리 화면(`inventory_screen.gd`/`.tscn`) - 아무 데도 연결 안 된 죽은 코드로 확인 후 삭제
- 레시피 아이템이 2개 이상 안 쌓이던 버그(`recipe_random` 등) - `stack_limit` 아이템별 오버라이드 도입으로 수정
- TAB 인벤토리 정렬/버리기 버튼을 텍스트 버튼 → 실제 아이콘(`icon_sort`/`icon_trash`) 이미지로 교체
- 우클릭으로 레시피를 배운 경우에도 머리 위에 "레시피를 배웠다" 메시지가 뜨도록 추가

### 1-3. 도감(수집) 시스템 버그 2건
- 아이템으로 배운 레시피가 도감에 안 뜨던 버그 - `CollectionManager`가 `CookingManager.recipe_learned` 신호를 안 듣고 있었음(조리로 배운 것만 듣고 있었음) - 수정
- 도감 획득 슬롯에 툴팁이 안 뜨거나 화면 이상한 위치에 뜨던 버그 - 원인 2가지: (1) 슬롯을 만드는 시점이 `_set_open(true)`의 mouse_filter 재귀 처리보다 앞서 있었음, (2) 내장 툴팁이 화면 3배 확대(`scale=3`) 구조를 제대로 인식 못 함 - 손수 만든 위치추적 툴팁으로 교체해서 해결

### 1-4. 자유 배치형 보관 상자(Storage Box) 시스템 신규
- 신규 오토로드 `StorageBoxManager` - 우디의 가구점에서 개당 1000골드로 구매, 손에 장착 후 원하는 타일에 자유 설치(현재는 Home 맵 한정)
- 처음엔 "바라보는 칸에 E키로 설치" 방식이었다가, 사용자 요청으로 "마우스 따라다니는 반투명 미리보기 + 클릭으로 설치"(스타듀 스타일)로 전면 교체
- 상자 하나당 24칸(6×4), 여닫는 그림 별도(닫힘 16×16 / 열림 16×32, 뚜껑 높이만큼 자동 오프셋), 문 열리는 지연(0.35초) + 삐걱 소리 후 UI가 뜨는 연출
- 정렬 버튼, 회수(빈 상자만) 버튼을 실제 아이콘으로 연결
- 과정에서 발견/수정한 버그:
  - `stack_limit == 1`이 "칸 하나에 1개"와 "총 보유 1개까지"를 혼동해서 상자를 2개째부터 못 사던 버그
  - 장비창에 상자를 끼면 보유한 개수 전부가 한 번에 손에 들리던 버그(스택형 장비 판정에 `stack_limit > 1` 조건 추가)
  - 장비창에서 드래그로 끼우기만 되고 빼기는 클릭만 되던 것 - 드래그로도 뺄 수 있게 통일
  - 못 버리는 도구를 버리려 할 때 실패음이 안 나거나, 두 번 눌러야 한 번만 나던 버그 2건

### 1-6. 캐릭터 색상 커스터마이징 시스템 (오늘 가장 많이 재설계된 부분)
사용자가 실제 그림을 그려서 계속 새로 넣어준 만큼, 요구사항도 계속 갱신되며 구조가 여러 번 바뀌었다:
- 머리색: 3단계 명도 마커 + RGB 슬라이더 팝업 → 팝업이 화면보다 커서(Godot 기본 ColorPicker 실측 298×450) 손수 만든 작은 팝업으로 교체
- 피부/눈동자색: 처음엔 고정 프리셋 목록(옆으로 넘기기) → "슬라이더/프리셋은 무슨 색이 나올지 모른다"는 피드백으로 색상환(색조 띠+채도명도 사각형, 미리보기 발밑에 항상 노출) 방식으로 재설계
- 최종적으로 머리색 팝업도 없애고, **모든 색(피부/눈동자/뺨/머리 3톤/상의/하의/신발/장신구 = 10개)을 색상환 하나 + 작은 스와치 탭으로 통합**, 탭은 1행 5개+2행 5개로 배치
- 뺨(볼터치)·상의·하의·신발·장신구 색은 전부 오늘 새로 요청되어 추가됨 - `player_body.png`의 기존 볼터치 마커, `player_outfit.png`/`player_shoes.png`/`player_accessory.png`의 명도 마커를 실측 확인 후 연결
- 머리/옷/장신구는 전부 "한 장의 그림에 스타일이 여러 줄 쌓인 시트" 구조로 통일(사용자가 직접 이렇게 그림) - 처음엔 옷/장신구가 폴더 스캔 방식으로 잘못 구현돼있던 걸 전부 헤어와 같은 시트 방식으로 교체
- 대머리(머리 0번 줄)를 "없음"으로 오인해 순환에서 뺐다가, 사용자가 "정식 스타일인데 왜 없어졌냐"고 지적해서 되돌림 - 장신구는 반대로 0번 줄이 실제로 빈 그림이라 "없음" 취급이 맞음(파일마다 다름, 실측으로 확인)
- 과정에서 실제 버그 1건 발견: 스와치 버튼에 `flat = true`를 걸어둬서 Godot이 평소 상태 배경을 아예 안 그리던 것 - 사용자가 캡처해서 보내준 스크린샷으로 바로 원인 파악(헤드리스 테스트로는 논리/배치는 맞는데 실제 그려지는지는 확인이 안 됐던 부분 - 스크린샷이 결정적이었음)

### 1-7. 치명적 버그: 게임 시작 전부터 시간이 흐르던 문제
- `TimeManager`가 오토로드라 씬과 무관하게 부팅 즉시 시계가 돌고 있었음 - 타이틀/슬롯선택/캐릭터생성 화면에 머무는 동안에도 게임 시간이 계속 흘러서, 실제로 며칠씩 지나가 버리는 문제(사용자가 "캐릭터 생성창만 띄워놨는데 이미 3일차"로 직접 발견)
- `is_running` 기본값을 false로 바꾸고, `main.gd`가 이미 매 프레임 하던 pause/resume 로직이 실제 게임 시작 시점에 자연스럽게 처음 켜지도록 수정(추가 코드 불필요)
- 같은 이유로 누적되고 있던 `GameManager.play_time_seconds`(플레이타임)도 동일하게 게이팅

### 1-8. 그 외 버그/개선
- 부팅 시 `randomize()`를 아무도 안 불러서 모든 무작위 로직이 매번 똑같은 결과만 내던 버그(만능 레시피가 항상 "피쉬앤칩스"만 나오던 원인) - `GameManager._ready()`에서 시드 흩뿌리도록 수정
- 타이틀 화면에서부터 빗소리가 나던 버그 - `AudioManager`가 부팅 즉시 배경음향을 켜던 걸 실제 게임 시작 시점까지 게이팅
- 1일차는 비가 안 오도록 확정(사용자: "생성하고 시작을 눌러야 진짜 게임이 시작되는데 그 즉시 비가 오는 건 첫인상으로 이상하다") - `WeatherManager`에 1일차 전용 굴림 추가
- 새 게임을 이미 저장된 슬롯에 만들면 자동저장(맵 이동 시)이 즉시 덮어써서 진행 상황이 사라지는 문제 - 새 게임 모드에서 사용 중인 슬롯은 아예 선택 불가로 막고, 대신 이어하기 화면에 슬롯별 "삭제" 버튼 추가(기존에 있었지만 안 쓰이던 `SaveManager.delete_save()` 연결)

## 3. 세션 중 발견한 교훈 (재발 방지용 기록)

- **헤드리스 테스트로는 논리/배치/저장은 확실히 검증되지만, 실제로 화면에 그려지는지(순수 렌더링 문제)는 못 잡는다** - `Button.flat=true`가 딱 이런 경우였다. 비슷한 "안 보인다" 리포트가 오면 로직을 더 파기 전에 스크린샷부터 요청할 것
- **테스트 스크립트가 실제 세이브 슬롯(특히 1번)을 절대 건드리면 안 된다** - 세션 중 테스트 스크립트가 1번 슬롯을 덮어쓰고 정리 단계에서 삭제하는 걸 보고 "실수로 진행 데이터를 지운 줄" 알고 사과했었는데, 실제로는 사용자가 직접 지운 것이었음(다행히 오해). 그래도 이후 테스트는 전부 빈 슬롯(3번)을 미리 확인하고 쓰는 걸로 통일함
- `player_shoes.png`를 처음 열어봤을 때 신발이 아니라 얼굴 그림처럼 보여서 사용자에게 확인 질문을 했는데, 그 사이 사용자가 실제 신발 그림으로 교체한 뒤였음 - 파일 내용을 두고 사용자와 의견이 갈리면, 다시 새로 읽어서 확인하는 게 맞다(캐시된 인상에 의존하지 말 것)
