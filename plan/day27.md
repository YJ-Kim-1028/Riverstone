# Day 27

day26(룩5~10 크롭 착수 전, HD 도구 포즈 시스템 신규 구현 직후) 다음 세션.
이번 세션은 **룩1~10 도구 포즈 마무리** + **고양이/강아지(NPC 선물) 시스템
신규 구현 전체** + **기본 언어 영어 전환** + **키 설정(행동키/미니맵) 기능**
을 진행.

## 룩5~10 도구 사용 포즈 크롭/삽입

- 사용자가 PixelLab으로 만들어둔 `preview_player_lookN.png`(256x320, 8x5
  그리드)에서 도구 포즈 프레임(row0의 south/west/east/north, idx 4~7)을
  크롭해서 `player_outfit_lookN.png`의 도구 프레임 슬롯(그룹당 offset 288,
  32x64)에 삽입 - PowerShell System.Drawing으로 4개 파일 일괄 처리.
- 크롭 좌표/그룹 순서(south=0,west=1,east=2,north=3)는 이미 완료된
  plain2의 결과물을 역산해서 확인 후 적용.

## 버그 발견: 룩1~4 도구 포즈가 사실 전혀 반영 안 돼있었음

- 사용자 리포트(2026-09-16) - "룩1번부터 동작포즈 안 돼": day26 로그에는
  "사용자가 직접 룩4까지 포즈 그림 작업 완료"라고 남아있었는데, 실제로
  `player_outfit_look1~4.png`의 도구 프레임을 idle 프레임과 픽셀 단위로
  비교해보니 **4방향 전부 픽셀 차이 0개**(완전히 동일한 복제본)였음 - 실제
  로는 크롭이 반영된 적이 없었던 것.
- `preview_player_look1~4.png`(이미 존재, 2026-09-16 새벽 작업분)에서 룩
  5~10과 동일한 방식으로 재크롭해서 삽입 - 삽입 후 픽셀 diff로 재확인
  (룩1: 2559픽셀 차이 등, 전부 정상 확인).
- "룩1번"이 "plain"(기본옷, 포즈 작업 포기했던 옷)과 헷갈릴 뻔했는데
  사용자가 "플레인 말고 그냥 룩1번"이라고 명확히 정정 - `plain`은 여전히
  포즈 없음(의도된 상태, 새 캐릭터는 선택 불가).
- 세션 마지막에 사용자가 "테스트 끝"으로 룩1~10 전부 정상 확인.

## 고양이(벨제)/강아지(셰퍼드) 호감도 50 선물 시스템 - 신규 구현

### 데이터/대사
- `belje.json`(+en/ja/zh) threshold 50: 축사에서 발견한 새끼 고양이를
  챙겨주다 플레이어에게 맡기는 대사(초안 승인받고 삽입, "sad" 이모션은
  사용자 지시로 제거).
- `shepherd.json`(+en/ja/zh) threshold 50: 지인이 떠넘긴 사냥개를 맡기는
  대사(초안 두 번 수정 - "귀찮더라" 문장, "사냥개라고~" 문장 각각 제거).

### 고양이/강아지 엔티티 (신규 파일, NPCWorldManager는 손 안 댐)
- `scripts/pets/cat.gd`, `scripts/pets/dog.gd` - 배회(랜덤 목적지 왕복,
  가끔 앉기/짖기) 상태머신. 고양이는 따라다니기 없음(강아지랑 동시에
  따라오면 서로 부딪혀 버벅거린다는 리포트로 제거), 강아지만 따라다님.
- `scripts/pets/cat_world_manager.gd`, `dog_world_manager.gd` - 각각
  `NPCManager.has_shown_event(npc_id, 50)` + 현재 맵(+날씨, 고양이만)
  조건으로 스폰/제거. main.tscn에 NPCLayer 형제로 CatLayer/DogLayer 배치.
- 고양이는 비오면 `home_interior.tmx`(레벨1~3 전부)로, 강아지는 비와도
  계속 `Home.tmx` 밖("강아지는 계속 밖에").
- 스폰 위치: 처음엔 플레이어 기본 스폰을 빌려썼는데 "문쪽에서만 왔다갔다"
  한다는 리포트로, 사용자가 Tiled에 전용 스폰 직접 추가
  (`cat_home_spawn`/`cat_interior_spawn`/`dog_home_spawn`) - 여러 번
  저장이 안 튕겨서(Tiled 탭별 저장 이슈) 재시도 끝에 완료.
- 크기: 고양이 0.45, 강아지 0.6(둘 다 초기 0.4에서 조정 - "강아지는
  고양이보다 커야 한다" 지시로 최종 확정).

### 발견/수정한 버그들(전부 2026-09-16~17)
- **잘못된 등장 조건**: `has_completed_event()`(호감도 임계값만 넘으면
  true, 대사 보기 전에도 true)를 썼다가 "벨제랑만 대화했는데 고양이+
  강아지가 동시에 생겼다"는 버그 - `has_shown_event()`(실제로 대사를 본
  적 있는지)로 교체.
- **방향 애니메이션 안 바뀜**: `_update_facing()`에서 정규화 벡터를
  `int()`로 잘라 `signi(0)==0`이 되던 버그 - 부호 직접비교로 수정.
- **크기 과대**: 스프라이트에 scale 자체를 안 넣어서 캐릭터 몸통보다도
  컸음 - scale 적용 + 이름표/호버판정 좌표 재보정.
- **이름표 항상 비어있음**: `set_pet_name()`을 `add_child()` 전(즉
  `_ready()` 전, `@onready _name_label`이 아직 null)에 호출해서 조용히
  무시되던 버그 - 호출 순서를 add_child() 뒤로.
- **이름표 호버 안 뜸**: 판정 기준점이 발밑 원점이라 실제 몸통(원점보다
  위쪽)에 마우스를 올려도 반경 밖으로 판정 - 판정 중심을 몸통 쪽으로
  올리고 반경 확대.
- **배회 중 벽에 막혀 멍청해보임**: 목적지가 벽 너머라 도달 불가능해도
  포기 안 하고 계속 같은 방향으로 붙어있던 문제 - 4초 타임아웃 후 새
  목적지 선택.
- **강아지 스폰 직후 안 따라옴**: `set_player()`가 스폰 순간 딱 한 번만
  호출되는데 그 타이밍에 Player 노드가 없으면 영영 안 채워짐 - 매 프레임
  스스로 재조회하도록 self-heal 추가.
- **재접속 시 고양이/강아지가 안 보임(간헐적)**: 재접속 직후
  WorldManager의 `_ready()`가 NPCManager 세이브 데이터 적용보다 먼저 도는
  race로 추정 - 100% 특정은 못 했으나, `TimeManager.minute_passed`(게임
  내 1분≈실제 10초)마다 자동 재확인하는 안전장치를 추가해서 완화.
- **걷기 애니메이션 버벅임**: 대각선 목적지로 갈 때 매 프레임 방향
  재계산에서 우세 축이 남↔동으로 계속 뒤집혀 애니메이션이 계속 처음부터
  재생 - `FACING_SWITCH_BIAS`(1.3배) 히스테리시스 추가(고양이/강아지 공통).
- **강아지 따라오기 버벅임**: FOLLOW_STOP_DISTANCE(32px) 경계에서 멈췄다
  움직였다 반복 - 정지/재개 거리를 32px/48px로 분리(히스테리시스).

### 고양이/강아지 호감도(신규, 2026-09-16~17)
- `NPCManager`에 `_pet_affection`/`_pet_clicked_today` 추가 - 벨제/셰퍼드
  기존 저장 블록에 필드만 얹음(새 SaveData 구조 안 만듦).
- **하루 한 번 클릭**으로만 호감도 상승, 클릭당 +5(처음엔 +1이었는데
  "의미있게 느껴지게" 5로 조정) - `_talked_today`와 동일한 매일 초기화
  패턴.
- 호감도가 실제로 오른 클릭에만 하트 아이콘이 머리 위로 떠오르는 이펙트.
- TAB→호감도 탭에 고양이/강아지 줄 추가 - **그 동물을 실제로 받은 뒤에만**
  나타남(`has_shown_event` 체크). 기존 NPC 목록(`NPCManager` 정식
  데이터)과는 완전히 분리해서 그림(스케줄/사망 등 다른 시스템과 안 얽히게).
- 아이콘: 처음엔 idle 그림을 그대로 썼는데, NPC 아이콘들이 전부 네모박스가
  그림 자체에 그려져 있는 스타일이라("내가 그려서 넣은거") 통일성이 안
  맞았음 - 사용자가 `assets/npc/icon/icon_cat.png`/`icon_dog.png`(15x16,
  박스 포함)를 새로 그려서 교체.
- **살해 후보 시스템과는 완전히 무관** - 벨제/셰퍼드 자신의 실제 호감도
  (`_affection`, 살해 후보 판정에 쓰임)와는 별개 변수(`_pet_affection`)라
  고양이/강아지를 아무리 클릭해도 살해 후보 등록에 영향 없음(사용자가
  직접 확인 질문, 답변 완료).

## 기본 언어를 영어로 전환

- `Localizer.DEFAULT_LANGUAGE`("ko", tr() 키 원본 언어 - 번역 시스템의
  기준값이라 그대로 둬야 함)와는 별개로 `INITIAL_LANGUAGE`("en") 신설 -
  언어 설정 파일이 없는 최초 실행에서만 적용, 한 번이라도 언어를 선택하면
  그 이후엔 저장된 값을 그대로 씀("처음 게임 깔고 켰을때 기본 언어가
  영어면 좋겠어").
- 관련해서 고양이/강아지 이름 짓기 프롬프트, 기본 이름, 설정 화면
  "행동키"/"미니맵" 라벨을 `strings.json`에 en/ja/zh로 신규 추가.

## 키 설정(행동키/미니맵 재지정) - 신규 구현

- `scripts/autoload/keybind_manager.gd`(신규, `Keybinds`) - Localizer와
  같은 정적 유틸리티 패턴(오토로드 아님, class_name 전역 접근),
  `user://keybind_settings.cfg`에 저장.
- 하드코딩돼 있던 `KEY_E`(player.gd 상호작용, dialogue_screen.gd 대사
  넘기기/선택 확정)와 `KEY_M`(minimap_screen.gd 토글)을 `Keybinds.
  get_keycode(...)` 참조로 교체.
- `settings_panel.tscn`/`.gd`(타이틀 화면 설정 + TAB 설정 탭 공유)에
  "행동키"/"미니맵" 두 줄 추가 - 버튼 누르면 다음 키 입력으로 바로
  재지정(ESC로 취소). 처음엔 9-슬라이스 버튼 스타일을 안 입혀서 "너무
  못생겼다"는 지적으로 다른 팝업들과 동일한 스타일 적용.
