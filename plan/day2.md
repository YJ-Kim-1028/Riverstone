# Day 2 개발 현황 정리

`day1.md`에 이어지는 문서. Day 1에서 "다음 순위 1번"으로 꼽았던 요리대 UI를 사용자가 직접 그린 디자인(참고 이미지 + 배경/슬롯/냄비 이미지 에셋)을 바탕으로 처음부터 끝까지 완성하고, 그 과정에서 레스토랑-NPC 연동, 여러 UI 공통 규칙, Godot 자체의 까다로운 렌더링 버그들을 발견/수정한 세션이다.

---

## 1. 오늘 완료한 것

### 1-1. 요리대 UI 전체 제작
- 사용자가 그린 참고 이미지와 에셋(냄비, 슬롯, 재료 인벤토리 틀, 배경 프레임)을 그대로 활용해 레이아웃 제작
- 냄비를 눌러 요리, 재료 2슬롯 선택, 재료 목록에서 재료 클릭해 슬롯 채우기
- 슬롯 2개가 다 차면 재료 목록이 어둡게 잠기고 클릭 불가 (직접 슬롯을 비워야 다시 선택 가능)
- 재료가 다 찼고 손님도 있고 아직 서빙 전이면, 냄비가 밝기만 천천히 두근거리며 "누를 수 있음"을 표시 (처음엔 크기 변화로 만들었다가 사용자 피드백으로 밝기 변화로 교체)
- 쥐약 토글: 켜려고 하면 확인 팝업("정말 넣으시겠습니까? 되돌릴 수 없습니다") 필수, 예/아니오로 결정. 끄는 쪽은 확인 없이 바로 처리. 한 번 켜면 요리창을 닫았다 열기 전까지 다시 끌 수 없음
- 요리 성공 시 창이 자동으로 닫히고, 실패(중복 서빙 등 예외 상황)면 냄비가 붉게 반짝이고 창은 열린 채 유지
- 재료/완성 요리 아이콘 전부 사용자가 지정한 위치(스프라이트 시트 행/열)로 연결

### 1-2. 레시피 습득 방식 변경
기존에는 "레시피 아이템을 먼저 써서 배워야만" 요리가 그 이름으로 나가고, 안 배웠으면 재료가 맞아도 무조건 "괴상한 요리"였다. 그런데 레시피를 배울 수 있는 실제 경로(상점 판매 등)가 하나도 구현돼 있지 않아서, 사실상 모든 요리가 항상 괴상한 요리로만 나가고 있었다. 사용자 지시로 **재료 조합이 맞으면 사전 학습 없이 바로 그 요리가 나가고, 동시에 레시피를 배우고 도감에도 등록되는 방식**으로 바꿨다. 안 맞는 조합만 여전히 괴상한 요리로 처리된다.

### 1-3. 레스토랑 ↔ NPC 연동
- 레스토랑에 앉은 손님이 실제로 좌석 그림 위치에 표시되도록 연결 (기존엔 "앉았다"는 내부 상태와 화면에 보이는 위치가 완전히 분리되어 있어서, 손님을 앉혀도 화면엔 안 보이는 문제가 있었음)
- 완성된 요리가 식탁 위에 그림으로 올라가고, 손님이 식사를 마치면 사라짐
- 식사를 마친 손님은 원래 자기 하루 일과(스케줄) 위치로 자동 복귀
- 좌석에 손님이 없으면 요리하기를 눌러도 요리창이 안 뜨고 "손님이 있을 때만 요리를 대접할 수 있다" 안내만 표시
- 이미 요리를 낸 손님(아직 식사 중)에게는 재요리가 안 되고 "이미 손님이 요리를 먹고 있다" 안내 표시
- 레스토랑을 닫으면, 아직 주문을 못 받은 손님은 바로 자리를 떠나고, 이미 식사 중인 손님은 그대로 유지
- 요리대 상호작용 범위를 벗어나면 열려 있던 요리창이 자동으로 닫힘 (자리를 벗어나도 계속 요리를 시도할 수 있던 문제 해결)

### 1-4. UI 공통 규칙 추가
- 요리창/상점창/인벤토리창 등 화면이 하나라도 열려 있으면: 이동 차단, 게임 시간 정지, 화면(창 제외) 어둡게 처리
- 상점 닫기 버튼을 요리창과 같은 스타일/크기로 통일
- 쥐약 확인 팝업의 흐릿하던 글자와 밋밋하던 예/아니오 버튼을 다른 화면과 같은 스타일로 교체

### 1-5. 테스트 편의 기능
- F9: 요리 재료를 즉시 인벤토리에 채워줌
- F10: 레스토랑을 강제로 열고 모든 요리대에 손님을 앉혀줌
- 둘 다 배포용 빌드에서는 자동으로 비활성화됨

## 2. 오늘 발견하고 고친 버그

작업 하나하나가 새 버그를 드러낸 세션이었다. 특히 아래 항목들은 이번 요리창 작업이 아니었으면 한동안 몰랐을 것들.

- **투명하게 숨겨둔 팝업이 클릭을 몰래 막던 버그**: 화면에 안 보이게(투명하게) 처리한 확인 팝업이라도, "클릭을 통과시켜라"는 설정을 따로 안 해두면 그 자리 클릭을 계속 막고 있었다. 쥐약 확인 팝업 뒤에 있던 재료 목록이 평소에도 클릭이 안 되던 진짜 원인이었다.
- **이미지를 원본보다 작게 줄이려면 "무시하고 강제로 줄여라" 설정이 꼭 필요**: 안 그러면 아무리 작게 지정해도 원본 크기로 되돌아가 위치가 어긋나 보인다. 슬롯, 닫기 버튼, 재료 아이콘 등 여러 군데서 반복해서 발견됨.
- **Godot 자체의 "동시 재생" 기능이 이 버전에서 조용히 먹통**: 여러 요소를 동시에 움직이려고 표준 기능을 썼는데, 에러도 없이 그냥 아무것도 움직이지 않았다. 요소마다 따로따로 움직임을 주는 방식으로 바꿔서 해결.
- **냄비가 커지는 애니메이션이 슬롯/독약까지 밀어내던 문제**: 부모가 커지면 자식들도 중심에서 멀어지는 방향으로 같이 밀려나서, 마치 위치가 움직이는 것처럼 보였다. 각 요소가 자기 자신을 기준으로 동시에 커지도록 구조를 바꿔서 해결.
- **화면에 그려 넣은 새 이미지가 하나도 안 보이던 문제**: Godot 편집기를 거치지 않고 이미지 파일만 새로 밀어 넣으면, 게임이 예전 캐시를 계속 쓰고 있어서 새 그림이 반영되지 않는다. 편집기를 한 번 열어 다시 읽게 해야 함.
- **손님 위치가 스케줄로만 정해지고 레스토랑 착석 상태와 전혀 연결이 안 되어 있던 구조적 공백**: 손님을 자리에 앉혀도 화면에는 원래 스케줄 위치에 그대로 있었다. 두 시스템을 연결해서 해결.
- **새로 만든 접시 그림이 타일 뒤에 가려 안 보이던 문제**: 다른 캐릭터들과 같은 "그리기 순서" 값을 안 줘서 바닥 타일에 가려지고 있었다.
- **머리 위 안내 문구가 긴 문장이 나오면 중심이 어긋나 보이던 문제**: 짧은 문구("E 이동" 등) 기준으로 폭을 좁게 고정해놔서, 긴 경고 문구가 그 상자를 넘쳐흘렀다. 상자를 넓히고 자동 줄바꿈을 켜서 해결.
- **쥐약 확인 팝업 글자가 흐릿하던 원인**: 요리창 전체가 확대되어 있는 만큼 글자 크기를 작게 줄여놨었는데, 도트 폰트가 그렇게 작은 크기에서는 뭉개져 보인다는 걸 놓쳤다. 팝업만 별도로 축소 배율을 상쇄시켜서, 다른 화면과 똑같은 정상 크기 글자를 쓸 수 있게 구조를 바꿨다.
- **요리창을 이미 열어둔 채로 재료를 얻으면 목록이 안 새로고침되던 문제**: 창을 열 때 한 번만 재료 목록을 그리고 있어서, 열어둔 채로 재료가 생기면 목록에 반영이 안 됐다.

## 4. 오늘 임의로 결정한 것들

- **레시피 습득 방식**: 사전 학습 없이 재료 조합만 맞으면 즉시 요리+레시피 습득+도감 등록 (사용자 명시적 지시로 기존 설계를 변경)
- **요리 "실패"의 의미 재정의**: "재료 조합이 레시피와 안 맞음"은 더 이상 실패가 아니다(괴상한 요리로 성공 처리). "손님이 없음", "이미 서빙함" 같은 상태 문제만 실패로 취급하고, 이때만 냄비가 붉게 반짝인다.
- **쥐약 잠금 규칙**: 한 번 활성화하면 요리창을 닫기 전까지는 되돌릴 수 없다 (사용자 명시적 지시).
- **모달 창 공통 규칙**: 요리창/상점창/인벤토리창류가 열려 있으면 항상 이동 차단 + 시간 정지 + 배경 어둡게, 라는 공통 규칙으로 통일 (사용자 지시를 일반화해서 앞으로 만들 다른 창에도 같은 규칙이 적용되도록 함).
