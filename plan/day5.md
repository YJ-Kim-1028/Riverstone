# Day 5 개발 현황 정리

`day4.md`에 이어지는 문서. Day4에서 다음 순위로 제안했던 두 가지 큰 항목(강제 기절→병원 기상 시스템, 요리 시스템 개편)을 오늘 전부 완료했고, 그 과정에서 상태창(TAB) UI와 장비 시스템도 신규로 붙었다. 나머지 시간은 요리 시스템 관련 UX를 사용자 피드백을 받아가며 여러 번 반복 개선하고, 그 과정에서 드러난 자잘한 버그들을 고치는 데 썼다.

### 1-5. 레스토랑 흐름 개선
- 영업 열기/닫기를 즉시 토글하지 않고 확인 팝업(`restaurant_confirm_popup`)을 거치도록 변경 — 문 앞에서 연타로 열렸다 닫혔다 하던 문제 방지.
- 레스토랑이 닫혀있을 때 조리대 앞에서 뜨는 문구를 "먼저 레스토랑을 열자."로 통일(손님 없음/영업 안 함 공통).
- 완성대 상호작용 프롬프트를 "E 완성하기" → "E 요리 제공"으로 변경.

### 1-6. 조리기구 화면(UI) 반복 개선
사용자 피드백을 받아가며 여러 차례 방향을 바꿈:
1. 처음엔 인벤토리 슬롯을 조리 슬롯으로 드래그하는 방식으로 구현 → 작은 슬롯에서 정밀하게 끌어다 놓기 불편하다는 피드백으로 **클릭해서 선택 + "조리 시작" 버튼** 방식으로 최종 확정.
2. 사용자가 준 조리기구 그림 4장(`assets/img/restaurant/img_pot/pan/knife/mixer.png`)을 처음엔 창 배경에 옅게 까는 장식으로 넣었다가, "슬롯에 넣는 느낌만 나고 요리하는 느낌이 안 난다"는 피드백을 받아 **재료 아이콘이 조리기구 그림 위에 얹힌 것처럼 보이는 `ToolVessel` 구조**로 재작업(그림+슬롯 겹침, 조리 중엔 살짝 흔들리는 애니메이션).
3. 슬롯 배경 그림(테두리)이 위화감을 준다는 피드백으로 슬롯 프레임만 안 보이게 처리(클릭 영역/기능은 유지).
4. 창 안의 진행바는 월드에 뜨는 미니 진행바(`KitchenProgressLayer`, 기구별 색상 지정)와 중복되고 시작하자마자 창이 닫혀 거의 안 보이므로 제거.

### 1-7. 그 외 자잘한 수정
- F9 디버그 재료 지급이 4개 조리기구 원재료(옥수수/감자/돼지고기/소고기/연어/고등어/오징어/상추/베리/우유)를 전부 포함하도록 확장.

## 2. 오늘 발견하고 고친 버그

- 조리창(특히 프라이팬 등 일부 기구)에서 ESC/닫힘 버튼이 안 먹던 문제 — 포커스 해제 로직이 시간정지 분기에 잘못 묶여 매 프레임 실행되며 클릭을 방해하던 것 + ESC 핸들러 자체가 누락돼 있던 것, 둘 다 수정.
- 완성대 화면에서 아이템 아이콘을 클릭하면 선택이 안 되고 슬롯 여백만 눌러야 되던 문제 — 화면 열릴 때 서브트리 전체에 `mouse_filter=STOP`을 재귀로 덮어쓰는 로직이, 동적으로 생성되는 그리드 슬롯의 아이콘/개수 라벨(원래 클릭 무시로 설정됨)까지 덮어써서 클릭을 가로채고 있었음.
- 레스토랑이 명시적으로 연 적 없는데도 아침 일찍 손님이 앉아있던 문제 — `is_open`이 하루가 바뀔 때 초기화되지 않아 전날 마감 전에 잠들면 다음 날에도 열린 상태로 이어지던 것.
- NPC가 식당 손님으로 처음 배정될 때 걷는 애니메이션 없이 좌석에 순간이동하던 문제 — "한 번도 추적 안 된 NPC"의 최초 위치 기준값을 잡을 때, 이미 좌석으로 배정된 상태의 좌표를 그대로 기준점으로 써버려 이동 거리가 0으로 계산되던 것.
- NPC가 식당에서 퇴장할 때(특히 스케줄상 화면에 없어야 하는 상태로 바뀔 때) 걸어나가지 않고 그 자리에서 즉시 사라지던 문제 — 화면에 보이는 NPC를 그냥 잊어버리기 전에 맵 출구까지 걸어나가게 하는 로직 추가.
- 로시(비 오는 날에만 존재하는 NPC)가 비 안 오는 날에도 레스토랑 무작위 손님 후보로 뽑히던 문제 — 손님 후보 생성 시 오늘 스케줄상 실제로 존재하는 NPC만 거르도록 수정(단, 플레이어가 직접 초대하는 경우는 예외로 옴, 사용자 확정).
- 드래그 미리보기 아이콘이 마우스 커서에서 멀리 떨어져 보이던 문제 — 커서가 아이콘 중앙에 오도록 오프셋 수정.
- 인벤토리/조리기구/완성대 등 슬롯을 공유하는 모든 화면에서 아이템 아이콘이 오른쪽 아래로 치우쳐 보이던 문제 — 공용 슬롯 씬의 아이콘에 `expand_mode`(EXPAND_IGNORE_SIZE) 설정이 빠져서 원본 텍스처 크기로 그려지려던 것이 원인.
- 완성된 요리 접시가 플레이어보다 앞에 그려지거나(1차 수정 시도), 반대로 책상 밑에 파묻혀 안 보이던 문제(2차) — 최종적으로 접시가 놓인 책상이 2행짜리 Y-sort 앵커로 묶여 있어 기준 좌표가 접시 위치와 다르다는 게 원인으로 확인, 레스토랑 팻말 오버레이가 쓰던 것과 같은 `WorldMap.get_tile_sort_y()`를 재사용해 책상과 같은 기준으로 정렬하도록 수정 후 실제 화면에서 정상 확인.

## 4. 오늘 임의로 결정한 것들

- 조리기구 화면은 드래그가 아니라 클릭+버튼 방식으로 확정(사용자 확정, 재차 강조됨).
- 완성대/조리기구 화면 모두 "인벤토리 전체를 보여주되 못 쓰는 아이템은 비활성화" 방식으로 통일(기존에 이미 확정됐던 것 유지).
- 로시처럼 스케줄상 오늘 아예 존재하지 않는 NPC는 무작위 손님 후보에서 제외하되, 플레이어의 명시적 초대는 예외로 허용(사용자 확정 — "초대했는데 왜 안 오지" 하는 혼란 방지).
- 청소 콘텐츠는 오늘 바로 구현하지 않고 game_design 문서 정리를 먼저 하기로 함(사용자 동의).

## 6. 사용자가 직접 해야 하는 것

- **직접 플레이 테스트** — 요리 시스템 전체 흐름(조리기구 4종 → 완성대 → 서빙), 상태창(TAB)/장비 드래그, 병원 기상/디버프, 접시 Y-sort가 실제로 자연스러운지.
- **레스토랑 컷오프 시간**: 몇 시로 당길지(또는 다른 방향으로 갈지) 결정해서 알려주기.
- **청소 등 부가 콘텐츠**: 하고 싶다면 game_design 문서로 먼저 정리.
- **이메일 자동발송 로직 재설계** 내용 알려주기 (계속 보류 중).
- **콘텐츠 작성** (5번 목록 "콘텐츠" 항목 전부): NPC 대사·이메일 본문·사칭 메일·선물 카탈로그·상점 가격·레시피 습득 경로.
- **에셋 준비**: 오디오 파일, 조리된 재료/레시피 아이콘 그림.
- **기획 문서 추가**: 농사/축산/낚시 규칙.
- 플레이어 스프라이트 / 메인 화면은 게임 완성 후로 미뤄뒀으니 지금은 손 안 대도 됨.
