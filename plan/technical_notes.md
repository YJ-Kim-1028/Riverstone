## 성능 최적화 (2026-08-08 "GameNew 성능 파일럿" 세션, day9.md 참고)

### 배경

원래 맵은 타일(16x16 칸) 하나하나가 전부 독립된 `Sprite2D` 노드로 그려지는 구조였다(Godot 내장 TileMap 미사용). 맵 하나에 타일이 수백~수천 개면 그만큼의 개별 노드를 GPU가 하나하나 따로 그려야 한다.

### 1. 렌더링 구조 전환 — Sprite2D → TileMapLayer

**왜 느렸나**: Godot에는 "배칭"(batching)이라는 최적화가 있다 — 같은 텍스처를 쓰는 여러 그림을 한 번의 그리기 명령으로 묶어서 처리하는 것. 개별 노드로 흩어져 있으면(특히 Y-sort 때문에 노드마다 위치/순서가 계속 바뀌면) 이 배칭이 잘 안 먹힌다. 셰이더까지 붙이면 아예 배칭이 깨진다(아래 "물결 효과 포기" 참고).

**해결책**: `TileMapLayer`는 Godot이 "이건 다 한 레이어의 타일들"이라는 걸 알고 있어서 내부적으로 훨씬 효율적으로 그려주는 전용 노드다. 20개 맵 전부 이걸로 전환.

**안전하게 전환한 방법**: 맵 20개를 한 번에 바꾸지 않고, `TILE_SET_RESOURCES`에 "이 맵은 새 방식 씀"이라고 등록된 맵만 TileMapLayer를 쓰고, 등록 안 된 맵은 자동으로 예전 방식(Sprite2D)을 그대로 쓰도록 설계. 홈맵 하나로 먼저 파일럿하고 문제없으면 나머지를 등록해서 확장하는 식으로 리스크를 분산.

**검증 방법**:
- 타일 그림 ID(GID)와 실제 칸 좌표가 새/구 방식에서 1:1로 정확히 일치하는지 확인
- 충돌 판정 결과가 완전히 같은지 (불일치 0건)
- 같은 맵을 전/후로 스크린샷 찍어서 비교(홈맵, plaza2, cowshed_interior)

**안 건드린 것**: 충돌/물/농사/발소리/경로탐색/조명 로직은 "타일을 뭘로 그리느냐"와 무관해서 그대로 둠.

### 2. 로딩 후 첫 이동 시 700ms 멈춤

**증상**: 맵 로딩 직후 처음 움직이면 잠깐 멈춤. 처음엔 이동 로직 자체가 문제인 줄 알았으나 실제 원인은 전혀 달랐음.

**진짜 원인**: NPC 스케줄 엔진이 게임 시작 후 첫 "1분" 틱에서 모든 NPC가 다음 목적지까지 얼마나 걸릴지 미리 계산한다. 거리를 재려면 목적지 맵을 "로드"해야 하는데, 이때 화면에 안 보이는 맵인데도 텍스처까지 통째로 실제 렌더링하고 있었다. 이게 NPC마다 반복되면서 한 프레임 안에 최대 38회, plaza1만 7회 — 합쳐서 약 700ms.

**해결책**: `WorldMap.load_map()`에 `render` 플래그 추가. `render=false`면 눈에 보이는 그림(텍스처/노드)은 아예 안 만들고, 충돌 판정·길찾기용 데이터만 뼈대로 생성. 거리 계산은 이 뼈대 데이터만 있으면 충분함. 맵별 계산 결과 캐싱도 추가.

**결과**: 700ms → 85ms. 반환값이 수정 전과 정확히 일치함을 확인. 남은 85ms를 완전히 0으로 만들려면 부팅 시 백그라운드에서 미리 다 계산해두는 더 큰 구조 변경이 필요해서 보류(수확 대비 공수가 안 맞는다고 판단).

### 3. 리소스 캐싱

- 타일셋(타일 그림 모음집) 리소스를 맵을 열 때마다 새로 안 만들고 `preload()`로 한 번만 만들어서 모든 맵 인스턴스가 공유하도록 함.
- Y-sort 때문에 특수 오프셋(`y_sort_origin`)이 필요한 타일은 "대체 타일"을 만들어야 하는데, 같은 오프셋 값이 여러 칸에서 반복되면 매번 새로 안 만들고 캐시에서 재사용(`_tile_alt_id_cache`, static 캐시 — 리소스 자체에 속한 정보라 인스턴스별이 아니라 공유).

### 4. 물결 효과 셰이더 포기

물 타일에 반짝이는 애니메이션을 셰이더로 시도(3가지 방식: UV 흔들기, 밝기 펄스, 반짝임 점멸). 개별 Sprite2D 구조에 셰이더 재질을 달면 배칭이 깨져서 타일 수만큼 렉이 늘어남을 확인. 효과 자체를 조정해서 될 문제가 아니라 구조적 한계라고 판단, 관련 코드/셰이더 전부 삭제하고 "성능 리스크"로만 기록. 이게 이후 TileMapLayer 전환(위 1번)의 동기가 됨.

### 5. 안전한 실험 절차

타일 렌더링 방식 전환은 모든 맵에 영향을 주는 큰 변경이라 실수하면 되돌리기 어려움. 작업 시작 전 git으로 단계별 커밋(롤백 지점) 확보 후 진행 — 문제 생기면 마지막 정상 상태로 되돌릴 수 있게.
