# Day 18

day17 세션에서 이어짐 - 친구에게 exe를 보내 플레이테스트를 맡기기 위한 익스포트/버그잡기 세션. 체포 엔딩 컷신 마무리 작업 후, 사용자가 직접 내보낸 exe를 실시간으로 테스트하며 리포트한 버그를 그때그때 수정.

## 체포 엔딩 컷신 마무리 (세션 전반)

- 첫 번째(경고) 총성 뒤 리액션 대사(감정 표현+독백) 추가
- 스토커 사망 처리(`NPCManager.kill_npc`) 시점을 `MurderManager._trigger_arrest_ending()`에서 실제 두 번째(치명상) 총성 직후로 이동 - 너무 일찍 죽은 걸로 처리돼 초상화가 조기에 회색 처리되던 문제 해결
- `_play_arrest_closing_narration()`에 `section` 인자 추가 - `aftermath_narration`에서 `{spared_name}` 치환이 안 되던 버그 수정
- 브금: 총성 전엔 `BGM_ARREST_ENDING` 반복, 총성 후엔 `BGM_ARREST_AFTERMATH` 반복, 엔딩 종료 후 원래 브금으로 복원(`AudioManager.restore_bgm_after_scene()`)
- 나레이션 페이드 타이밍 재설계(사용자 지시) - `closing_narration` 직후 화면 밝아지도록 변경
- `_maybe_resume_arrest_ending()` 추가 - 게임 재시작 시 엔딩 컷신 도중 저장된 세이브를 안전하게 재개(기존 `_maybe_resume_accomplice_ending()`과 동일 패턴)
- 헤드리스 자동 재현 하네스로 "화면이 안 밝아진다"는 리포트를 직접 검증 - 실제 버그가 아니라 나레이션이 끝까지 이어지는 동안 의도적으로 화면을 계속 어둡게 유지하는 설계였음을 확인(오해 해소)

## 익스포트 빌드 전용 UI 버그 대량 수정 (세션 중반~후반)

친구 테스트용 exe를 직접 실행해보니, 에디터 Play에서는 재현되지 않고 **내보낸 빌드에서만** 여러 화면이 좌측 상단에 눌려 뜨거나 클릭이 안 먹는 문제가 연달아 발견됨. 두 가지 서로 다른 원인이 섞여 있었음:

### 원인 1 - 앵커 기반 위치가 창이 완전히 자리잡기 전 값으로 굳는 버그 (export 전용)
- 처음엔 "자기 자신에게 앵커/오프셋 값을 재대입"하는 방식(`_refresh_layout()`)으로 대응했으나, 값이 이미 같으면 엔진이 재계산을 안 해서 실제로는 효과가 없었음(여러 차례 재발로 확인)
- 진짜 해결책은 `set_anchors_and_offsets_preset()`을 실제로 호출하는 것 - 화면 루트가 전체화면(0/0/1/1)이면 `PRESET_FULL_RECT`, 가운데 고정 크기 박스면 `PRESET_CENTER` + `PRESET_MODE_KEEP_SIZE`(크기는 유지한 채 실제로 다시 계산)
- 적용 대상: 이어하기/새로하기 슬롯 선택창, 캐릭터 생성창, 언어 설정창, 종료 확인 팝업, 슬롯 삭제 확인 팝업(이상 전체화면), 컴퓨터(메일)창, 상점창, 상태창(TAB)(이상 가운데 고정 박스)
- 나머지 팝업(도감/조리대/낚시/보관함/주크박스/책읽기/각종 확인창 등)은 1차 대응(`_refresh_layout()`)만 적용된 상태 - 아직 실제 리포트가 없어 그대로 둠, 같은 증상 나오면 위 방식으로 교체 필요

### 원인 2 - 아이콘 오버레이가 mouse_filter 재귀 처리에 덮어써지는 버그
- 각 화면이 열고 닫힐 때 하위 트리 전체의 `mouse_filter`를 STOP/IGNORE로 재귀 강제하는 공통 패턴(`_apply_mouse_filter_recursive`)을 쓰는데, 그 안에 있던 순수 그림용 아이콘(Icon 노드, 클릭이 밑의 진짜 버튼까지 통과하도록 `.tscn`에 `mouse_filter=IGNORE`로 지정해둔 것)까지 매번 STOP으로 덮어써버려서, 정작 버튼 자체의 클릭이 한 번도 안 터지는 문제
- 낚시 미니게임의 물고기, 조리대의 완료 상태 아이콘, 장비 슬롯(드래그로 빼기)에서 재현 - 아이콘이 버튼 전체를 덮는 경우 완전히 안 눌리고, 부분만 덮는 경우 "칸 끝에 걸쳐야만" 눌리는 식으로 나타남
- 해결: `refresh()` 등 화면이 열릴 때마다 항상 다시 호출되는 지점에서 해당 아이콘의 `mouse_filter`를 매번 다시 IGNORE로 되돌리는 자가치유 코드 추가

### 기타 UI 버그
- TAB(상태창) 안의 자식 팝업(종료 확인창)까지 재귀 mouse_filter 처리에 걸려, 그 팝업의 투명한 Dim 배경이 화면 전체를 덮은 채 STOP 상태로 남아 TAB 안의 다른 버튼들을 다 가로막던 버그 수정(TAB의 재귀 처리에서 이 팝업만 제외)
- TAB 키가 컴퓨터(메일) 등 다른 화면이 이미 열려 있어도 그 위에 겹쳐 열리던 문제 - main.gd의 `_is_any_modal_open()`을 콜백으로 받아 열기 전에 확인하도록 수정
- TAB 창 안에서 버튼을 한 번이라도 클릭하면 그 버튼이 키보드 포커스를 가져가서, Godot이 다음 Tab 키 입력을 "포커스 이동"으로 먼저 먹어버려 창이 안 닫히던 문제 - TAB 키 처리를 `_unhandled_input`에서 `_input`으로 옮기고 `set_input_as_handled()`로 확실히 소비

## 게임플레이 버그 수정

- **선물이 대화 후엔 아예 안 되던 버그** - NPC 감지 함수(`get_nearest_talkable_npc`)가 "오늘 이미 대화한 NPC"를 통째로 걸러내는데, 선물 주기도 같은 함수로 대상을 찾다 보니 한 번 대화한 NPC에게는 그날 선물을 줄 수 없게 막혀 있었음. 손에 선물을 들고 있을 때만 이 필터를 건너뛰도록 `ignore_talked_today` 파라미터 추가
- 레스토랑이 영업 종료 시간(4시)에 자동으로 닫히는데(플레이어가 안에 있어도) 안내 문구가 하나도 없어서 조용히 닫히던 문제 - `TimeManager.restaurant_closed`(자동 닫힘 전용 신호)에 걸어서, 그 순간 레스토랑 안에 있으면 안내 문구 표시
- 장비 슬롯에 이미 뭔가 장착된 상태에서 다른 아이템으로 교체 시, 기존 아이템을 인벤토리로 돌려줄 자리가 없으면 조용히 실패하던 것 - 실패 시 안내 문구 추가

## 문구/디자인 다듬기

- 어셔의 책 아이템 설명에 "우클릭하면 읽을 수 있다" 안내 추가

## NPC 대사집 리뷰 (세션 막바지)

기획 검토용으로 전체 NPC 데이터를 한 번 훑어봄(수정은 안 함, 리포트만):
1. 셰퍼드 호감도 100 대사가 플레이어를 향한 로맨틱한 구애처럼 읽힘 - 벨제(아내)+모카(불륜)에 이어 플레이어까지 얽히는 방향인데 기획 문서에 근거 없음, 확인 필요
2. 우디 호감도 85 이벤트가 수습 없이 자살 충동을 직설적으로 던지고 끝남 - 다른 NPC들의 "가면 벗겨지는 순간"과 톤이 다름
3. 스토커(어셔) 초기 메일 일부가 애원/소심한 톤 - 이전에 세 번 반려했던 "자신감 있는 사이코패스" 방향과 반대
4. 라마 호감도 60 이벤트에 이샤의 의료과실 관련 무거운 설정이 이샤 본인 파일/기획문서 없이 등장
- 참고: 이샤가 플로라 질투할 때 "년" 표현이 60/80/110 세 군데 반복(의도된 에스컬레이션이면 무관)
