### 가구 원목 색 "뿌옇다" 이슈 - 원인 규명 완료(코드 버그 아님으로 결론)

- 세이브 파일(`chair@b88c5f-...`)을 직접 까본 결과, 사용자가 스크린샷으로 보여준 의자는 **WOOD_PALETTE를 교체하기 전(구버전 팔레트)에 산 물건**이었다 - 코드는 정상 동작 중이었고 D6D6D6(가장 넓은 면적) 마커에 고른 색을 그대로 넣는 로직(day10에서 확정)도 잘 작동하고 있었다.
- 새로 산 색(a64c3d, Mahogany)은 채도 63%로 게임 평균보다 오히려 쨍한 색으로 확인됨 - 색 선택 자체는 문제가 아니었다.
- `chair.png` 원본을 직접 픽셀 스캔해서 색1 마커 비율을 확인: D6D6D6 51% / A8A8A8 14% / **727272(-38% 어둡게) 35%**. 데스크류 등 다른 가구는 D6 비중이 90% 이상이라, 의자만 유독 어두운 마커 비중이 높아서 같은 색을 골라도 더 칙칙해 보이는 것으로 결론. 해결책 두 가지 제시(코드에서 `COLOR1_DARK_MIX`를 더 낮추기 / 그림에서 727272 비중을 줄이기) - **아직 사용자 결정 대기, 다음 세션에 이어갈 것.**
- `WOOD_PALETTE`(색1)와 `SWATCH_PALETTE`(색2/3)를 사용자 지정으로 총 세 차례/두 차례 교체함. **최신 확정값**:
  - `WOOD_PALETTE`(12색, `scripts/ui/shop_screen.gd`): Dark Walnut(472f1d), Classic Oak(8d562c), Golden Oak(c97a22), Orange Oak(d97f1f), Honey Wood(e19328), Amber Wood(e88a1a), Autumn Wood(c45a1e), Cherry Wood(b63c2c), Red Mahogany(922e24), Pumpkin Wood(d96a18), Copper Wood(c85b19), Bright Maple(f0a43a)

### 가구 색상 고르는 창 - 미리보기 그림이 안 보이던 버그 (수정 완료)

- 원인: `shop_screen.gd`의 `PreviewRect.expand_mode = EXPAND_IGNORE_SIZE`(원목 뿌옇음 조사 중 방어적으로 추가했던 코드) - PreviewRect의 `custom_minimum_size` 폭이 0으로 되어있어서, 텍스처 크기를 무시하니 실제 폭도 0으로 굳어버려 그림이 안 보였음. 모든 가구/장식에서 재현되는 전역 버그였음.
- 기본값(`EXPAND_KEEP_SIZE`)으로 되돌려서 해결.

### 집 확장 - 아이콘 연결 + 치명적 버그 두 건 수정

- `house_upgrade_icon.png`(사용자가 그림) 연결 완료 - `shop_screen.gd`의 단색 placeholder 제거.
- **버그 1 (수정 완료): 집을 사도 안 넓어짐.** `home_map.gd.get_map_path()`가 레벨 2/3 `.tmx` 파일 존재 확인에 `ResourceLoader.exists()`를 썼는데, `.tmx`는 XMLParser로 직접 읽는 원시 파일이라 Godot 리소스 로더 형식이 아니라서 이 함수가 항상 `false`를 반환 → `house_level`은 정상 저장되는데도 매번 레벨 1 지도로 조용히 되돌아갔음. `FileAccess.file_exists()`로 교체해서 해결.
- **버그 2 (수정 완료 + 재발 방지 시스템 구축): 집 확장 후 기존에 놓아둔 물건이 허공에 뜸.** 사용자가 Tiled에서 레벨2 맵을 다시 그리며 기존 바닥을 아래로 6칸 밀었는데, 이미 저장된 배치 좌표는 그대로라 어긋난 것. 단순히 세이브 파일 하나만 패치하면 "다른 사용자가 또 집을 넓히면 또 뜬다"는 사용자 지적으로, **근본 수정**: `EconomyManager.upgrade_house()`가 레벨업 시 옛/새 지도의 "home_enterance"(현관) 스폰 좌표를 자동 비교해서 그 차이만큼 가구/바닥장식/벽장식/보관함 좌표를 전부 같이 옮기도록 구현(`WorldMap.get_room_anchor_shift()` + 4개 매니저의 `shift_map_placements()`). 오프셋을 하드코딩하지 않고 그때그때 실제 `.tmx` 두 장을 비교해서 구하므로, 나중에 지도를 또 고쳐도 값이 어긋나지 않는다. 기존 세이브(`save_slot_2.json`)는 보관함 하나(`home_interior`의 9,4→9,10)만 직접 보정함(백업: `save_slot_2.backup_before_house_shift.json`).

### 가구/바닥장식/벽장식 배치 효과음 교체

- 기존엔 `SFX_DIGGING`(흙 파는 소리)이 나고 있었는데 배치 느낌과 안 맞아서 "소리가 없다"고 느껴짐. 장비창/조리대/서빙대에서 이미 쓰던 `SFX_UI_SLOT_IN`으로 통일(furniture/floor_decor/wall_decor 3개 매니저).

### 도구 사용 애니메이션 - 방향 확정 (그림은 다음 세션)

- 몸/옷마다 방향당(4방향) "사용 포즈" 프레임 1장씩 추가하는 방식으로 결정. 도구 종류(괭이/물뿌리개/낚싯대/망치)는 별도로 그리는 게 아니라, 같은 포즈 위에 작은 도구 아이콘을 손 위치에 겹쳐서 구분.
- **머리(12종)/장신구(12종)는 새로 그릴 필요 없음** - 팔 동작과 안 겹치는 부위라, 사용 포즈 동안 기존 idle 프레임을 코드에서 그대로 고정해서 보여주면 됨(96프레임 절약). 몸(1종) + 옷(3종)만 4방향씩 그리면 됨.
- **다음 세션 시작 시**: 사용자가 몸/옷 use-pose 그림을 그려오면, 애니메이션 상태 전환 + 머리/장신구 고정 + 도구 오버레이 합성 코드는 Claude가 작업.

### 주크박스 음원 구매 방식 변경 (수정 완료)

- 기존엔 `JukeboxManager.is_unlocked()`가 `InventoryManager.has_item(item_id, 1)`로 판정해서, 음반을 인벤토리/상자에 실제로 들고 있어야만 곡이 잠금 해제됐다(버리면 다시 잠김) - 사용자 지적대로 "산 음원은 인벤토리에 있어도 할 게 없는 죽은 아이템"이었음.
- `is_unlocked()`를 `ShopManager.get_purchase_count(item_id) > 0`(한 번이라도 구매한 적 있는지) 기준으로 변경 - 이제 영구 해금, 아이템을 버려도 잠기지 않음.
- `ShopManager.buy()`에 `JukeboxManager.is_record_item(item_id)` 분기 추가(`_buy_jukebox_record()`) - 집 확장/인벤토리 확장과 같은 패턴으로, 음반 구매는 `InventoryManager.add_item()`을 아예 안 타고 골드 결제 + 구매 기록만 남긴다. 구매 즉시 주크박스 목록에만 곡이 추가되고 인벤토리엔 아무것도 안 생김.
- `is_record_item()`은 `songs.json`의 `item_id` 필드들과 대조해서 판단 - 나중에 곡이 추가돼도 `shop_manager.gd`를 따로 고칠 필요 없음.
- 기존 세이브는 이미 `purchase_counts`에 두 곡 다 기록돼 있어서 그대로 해금 상태 유지. 상자 안의 옛 `record_chiptune`/`record_city_pop` 아이템은 수정 전에 산 잔재라 이제 의미 없는 소지품 - 버려도 무방.
