# Day 3 개발 현황 정리

> **2026-07-30 추가 세션**: 아래 1~5번은 오전 세션 내용. 오후에 사용자가 컴퓨터 UI를 데스크탑+창 방식으로 다시 설계해서 완전히 새로 그렸고, 그 내용은 맨 아래 "6. 오후 재작업" 절 참고. 온라인샵/이메일함 자체의 존재는 그대로지만 화면 구조와 이메일 데이터 모양이 바뀌었다.

`day2.md`에 이어지는 문서. Day2 문서의 "다음 순위 1번" 컴퓨터 UI(온라인샵/이메일함)를 완성했다.
사용자가 컴퓨터 화면 그림을 직접 그릴 예정이라, 이번 세션은 그림에 의존하지 않는 부분(백엔드 로직 + 기존 상점/요리창과 동일한 재사용 가능한 자리표시 UI)까지만 진행했다.

## 1. 오늘 완료한 것

### 1-1. 온라인샵
`ShopManager`에 이미 온라인 구매/익일 9시 배송 로직이 다 있었어서(Day1~2에서 구현됨), 새로 만든 건 `ShopManager.get_shop_mode(shop_id) == "online"`인 상점만 걸러서 상점 이름별로 묶어 보여주는 화면(`online_shop_panel.gd`/`.tscn`) 뿐이다. `shop_screen.gd`와 완전히 같은 구매 흐름(`ShopManager.buy()`)을 그대로 탄다.

### 1-2. 이메일함 (시스템 본체 신규 구현)
새 오토로드 `EmailManager` (`scripts/autoload/email_manager.gd`)를 추가했다.
- 인박스 저장(수신 메일 배열, 읽음 여부, 영구 보관 — email.md 그대로)
- 매일 09:00(`TimeManager.day_changed`)마다 살아있는 NPC 전원에 대해 발송 여부 판단:
  - `gift_thanks` — 전날 선물을 받았으면 100% 발송 (신규: `NPCManager.gift_given` 신호 추가, `give_gift()`에서 emit)
  - `event_invite` — 오늘 레스토랑 방문객 큐에 있으면 확률적으로 발송 (신규: `RestaurantManager.get_todays_visitor_ids()` getter 추가)
  - `greeting` — 그 외엔 확률적으로 발송 (필러 메일)
  - `story_progress` — 살인 발생(1건/2건) 트리거만 우선 연결, NPC당 한 번만
- 플레이어 → NPC 메일 발송 1일 1회 (`NPCManager.send_email()` 재사용, 호감도 +3은 기존 로직 그대로)
- 레스토랑 초대장은 기존 `RestaurantManager.invite_npc()`를 화면에서 그대로 호출 (이미 1일 1회 제한 보유)
- `save_manager.gd`에 `email` 필드로 연동 (기존 필드는 건드리지 않음, 다른 시스템들과 동일한 패턴)

### 1-3. 컴퓨터 UI
- `computer_screen.gd`/`.tscn` — 탭 2개(온라인샵/이메일함)로 전환. `shop_screen.gd`와 동일한 "항상 visible=true, modulate.a + mouse_filter로 열고 닫기" 패턴 사용
- `email_panel.gd`/`.tscn` — ui.md 레이아웃(좌: 메일 목록 / 우: 메일 내용) + 하단에 NPC 선택 후 "안부 메일"/"초대장" 버튼
- `main.gd`의 `computer_interacted` 신호를 `computer_screen.open()`에 연결, `_update_ui_blocking()`에도 포함시켜 다른 모달과 동일하게 이동 차단/시간 정지/화면 어둡게 적용
- 전부 기존 자리표시 에셋(`frame_9slice.png`, `btn_close.png`, 기본 테마 버튼) 재사용 — 사용자가 그림을 그리면 `.tscn`만 교체/조정하면 됨 (Day1의 인벤토리/상점 화면과 동일한 워크플로우)

## 4. 오늘 임의로 결정한 것들

- **필러 메일 발송 확률**: email.md에 빈도 규정이 없어서 `EmailManager.GREETING_CHANCE_PER_DAY = 0.2`, `EVENT_INVITE_CHANCE_PER_DAY = 0.5`로 임의 지정. 스크립트 상단 상수라 값만 바꾸면 됨.
- **`special_day`(기념일 메일) 트리거는 아직 미구현**: 게임 내 캘린더/기념일 규칙 자체가 정의된 곳이 없어서, 이 카테고리는 데이터에 내용이 채워져도 지금은 발송되지 않는다. 캘린더 규칙이 정해지면 `EmailManager`에 `_maybe_send_special_day()`를 추가하면 됨.
- **`story_progress` 트리거는 살인 발생 2종만 연결**: `first_murder_occurred`/`second_murder_occurred` 외의 트리거 이름은 아직 해당 조건을 판단할 시스템이 없어서 매칭되지 않음 (스토리 진행에 따라 추가 예정).

## 6. 오후 재작업 - 데스크탑+창 방식 컴퓨터 UI

사용자가 "메일은 우편이 아니라 컴퓨터 안 이메일 앱"이라며 `assets/ui/`에 실제 에셋 10종(`computer_background.png`, `computer_window.png`, `frame_computer_leftbox.png`, `btn_computer.png`, `btn_computer_back.png`, `btn_computer_close.png`, `icon_computer_email.png`, `icon_computer_shop.png`, `icon_computer_email_new/old.png`)과 `references/`에 참고 스케치 4장(`refer_computer_background/mail/mail_detail/mail_write.png`)을 올리고, 구조를 텍스트로 상세히 설명해줬다. 그걸 바탕으로 아래처럼 전면 재작업했다.

### 구조 변경
- **데스크탑 개념 도입**: 컴퓨터를 열면 바탕화면(`computer_background.png`)에 아이콘 2개(이메일/샵)만 보이고, 클릭해야 각각 창(`computer_window.png`)이 뜬다. 예전의 "탭 2개짜리 화면"은 폐기.
- **이메일 앱 내부**: 좌측 사이드바(`frame_computer_leftbox.png`, 수신함/발신함/메일쓰기 버튼) → 목록(아이콘+제목+날짜) → 자세히보기(뒤로가기+제목+보낸/받는사람+내용+날짜) 흐름. 자세히보기/메일쓰기 화면에서는 사이드바가 사라지고 좌측 상단 뒤로가기 버튼(`btn_computer_back.png`)만 남는다.
- **메일쓰기**: 제목/수신인선택/모드버튼(안부메일·초대장)/내용/날짜/**전송 버튼**(날짜 아래 - 처음엔 빠뜨렸다가 사용자가 알려줘서 추가). 안부메일 모드는 100자 제한 자유 작성 후 전송하면 발신함에 저장. 초대장 모드는 내용이 고정 문구로 잠기고 전송하면 `RestaurantManager.invite_npc()` 호출(발신함에는 저장 안 함 - 사용자가 안부메일만 저장된다고 명시).

### 새/변경 파일
- `data/npc/README.md` — `emails` 항목 모양을 `[lines...]`에서 `{title, lines}`로 변경 (13개 npc json은 전부 빈 배열/객체라 실제 파일 수정은 불필요, 문서만 갱신)
- `EmailManager` — title 추출 반영, 발신함(`_sent`) 추가, `compose_and_send(npc_id, title, content)` 신규. **주의**: 매일 09시 자동 발송 판정 로직(확률/우선순위)은 스키마 적응만 하고 그대로 둠 - 사용자가 이 부분은 따로 다시 설계하겠다고 했음.
- `scripts/ui/mail_app.gd`, `mail_list_panel.gd`, `mail_detail_panel.gd`, `mail_compose_panel.gd` + 대응 `.tscn` 4개 — 이메일 앱 신규
- `scripts/ui/computer_screen.gd`/`.tscn` — 데스크탑+아이콘 방식으로 전면 재작성
- `scripts/ui/online_shop_panel.gd`/`.tscn` — 배경/닫기 버튼을 `computer_window.png`/`btn_computer_close.png`로 교체 (내용/구매 로직은 그대로)
- (삭제) `email_panel.gd`/`.tscn` — 탭 방식 화면, 위 새 구조로 대체됨

### 테스트
헤드리스 부팅 시 새 PNG 10종이 에디터를 거친 적 없어서 "No loader found" 파싱 에러가 났다 (day1의 "이미지 캐시" 버그와 같은 계열 - `.import` 사이드카가 아예 없는 상태였음). `Godot ... --headless --import`로 임포트 패스를 한 번 돌려서 해결. 이후 `--quit-after 60`, `--fixed-fps 1 --quit-after 1000`(하루 경계 포함) 둘 다 에러 0개.

### 확정 안 된 채로 임의로 넘어간 것 (가벼운 것들, 확인 원하면 말해줘)
- 버튼 배경(`btn_computer.png`) 스트레치 여백값(3/3/1/1) — 실제 버튼 크기에 맞는지 안 봄
- 아이콘/사이드바/버튼 좌표는 참고 스케치 비율만 보고 눈대중으로 잡음 (Day1 관례대로 에디터에서 직접 조정 필요)
- 컴퓨터 전체 화면 배율 3배(80x48 → 240x144, 화면 320x180 중앙)로 잡음
- 메일쓰기 날짜 표시 형식은 "N일차"로 임의 지정
- 모드 버튼(안부메일/초대장) 중 어느 게 선택됐는지 시각적으로 강조하는 처리는 아직 없음 (기능은 정상 동작)

### 사용자가 직접 해야 하는 것
- **직접 플레이 테스트**: 집의 "computer" 오브젝트 앞에서 E → 아이콘 클릭 → 이메일 앱(수신함/발신함/메일쓰기)·샵 창 동작 확인
- 위 "확정 안 된 채로 넘어간 것" 항목들이 마음에 안 들면 알려주면 조정
- 이메일 자동발송 판정 로직(확률/우선순위)은 여전히 대기 중 - 새로 설계한 내용 알려주면 그때 반영
- Day1~2 문서에 남아있던 항목(NPC 대사·이메일 본문 내용, 상점 가격, 오디오/스프라이트 에셋 등)은 계속 미해결

## 7. 이어지는 세션 - 이메일 UI 폴리싱 + 책장(도감) UI 신규 + 대량 버그 수정

6번 이후 별도 요약 없이 이어진 세션(밤~새벽) 내용. 예정에 없던 버그 수정이 대부분을 차지했고, `day2.md`의 "다음 순위 1번"이었던 책장(도감) UI는 이번에 새로 완성했다.

### 7-1. 이메일 앱 UI 세부 폴리싱
사용자가 실제 에셋을 그려 올릴 때마다 반복 조정한 내용(전부 `mail_app.gd`/`mail_list_panel.gd`/`mail_detail_panel.gd`/`mail_compose_panel.gd`와 대응 `.tscn`):
- 수신함/발신함/메일쓰기 버튼 및 폰트 크기 여러 차례 축소, leftbox를 창 안쪽으로 이동
- 닫기(X) 버튼 크기 1/4로 축소, 텍스트 색상 전부 흰색 → 검정색으로 통일(목록/자세히보기/메일쓰기 제목·내용·hint 포함)
- NPC 선택 select box가 화면을 뒤덮던 버그 수정(크기 축소)
- 메일쓰기: leftbox 숨김, 전송 버튼 배경 이미지 누락 수정, 제목 미작성 시 전송 막고 안내 팝업 추가, 제목 disabled 범위를 텍스트박스 크기에 맞게 축소하고 disabled 오버레이 색을 제목/내용 동일하게 통일
- 발신함에 "초대 내역" 버튼 신설(날짜+수신인만 표시), 초대장 제목을 "레스토랑 초대장"으로 고정(기존엔 고정 안 돼 있었음), 초대문구 오타("우리 레스토랑 레스토랑" → "우리 레스토랑에 초대합니다!") 수정
- 목록에서 메일 여러 개가 한 자리에 겹쳐 보이던 정렬 버그 수정
- 발신함/수신함 사이드바에 상대방 초상화 표시 추가(발신함=수신인, 수신함=발신인)
- "받는 사람" → "수신인"으로 문구 변경
- 컴퓨터 바탕화면에 전원 버튼(`icon_computer_onoff.png`) 추가로 ESC 없이 종료 가능, 발신함 아이콘 `icon_computer_send.png`로 교체
- 수신 테스트용 디버그 단축키 추가(NPC로부터 메일 5개 즉시 수신)
- **메일 자동발송(확률/우선순위) 로직은 이번에도 손대지 않음** - 사용자가 재설계 예정, 스키마(title 필드, 발신함)만 이번 세션에 추가로 반영됨

### 7-2. 취침 → 다음날 전환
- 기존엔 침대에서 E로 즉시 다음날 전환됐는데, 사용자 요청으로 "잠에 드시겠습니까? 예/아니오" 확인창(`scenes/ui/sleep_confirm_popup.tscn` 신규)으로 변경. 침대 타일에 닿으면 자동으로 뜨고, 같은 자리에 계속 있어도 재확인 안 뜸(타일을 벗어났다 다시 밟으면 재확인)
- 예 선택 시: 화면 페이드아웃(검게) → 실제 날짜 진행(`TimeManager.sleep_now()` 신규) → 화면 중앙에 "N일차" 1.2초 표시 → 페이드인. 연출 중엔 이동/시간 정지
- 아니오 선택 시 아무 처리 없음
- 확인창 예/아니오 버튼이 한쪽으로 쏠리던 버그 수정(양옆 패딩 대칭화)
- `SaveManager.sleep_and_save()`(침대 오브젝트 생기기 전 미리 만들어둔 빈 함수)는 이제 안 쓰여서 정리함

### 7-3. 상호작용 프롬프트 확장 + 레스토랑 표지판

### 7-6. Y-sort/충돌 대장정 (핵심 미해결 이슈)
나무 한쪽만 플레이어 뒤로 그려짐 → 건물 지붕 위로 머리가 뜸 → 레스토랑 화단/가로등/벽걸이그림 우선순위 뒤바뀜 → 레스토랑 파티션 벽이 얼굴 앞에 그려짐 등, 연달아 발견된 버그를 그때그때 고쳐나갔다. 근본 원인은 `home_map.gd`가 TMX 타일 레이어를 "칸 단위"로 읽어서 "이 칸들이 하나의 물체다"를 매번 추론해야 하는 구조라는 점(나무 밑동+잎, 건물 벽+지붕처럼 여러 칸에 걸친 물체마다 추론 규칙이 계속 늘어남). 이번 세션에 고친 것들:
- 나무/건물처럼 세로로 이어진 물체의 "대표 정렬 행"을 구하는 로직(`_compute_run_bottom_rows`)을 여러 차례 재설계: 레이어별 독립 처리 → "open"(밑동만 막힘, 나무·가로등류)/"solid"(전부 막힘, 건물류) 카테고리 분리 → 인접 열 병합은 같은 카테고리이면서 "open"끼리만 허용(무관한 인접 구조물이 병합되던 버그 방지) → 자기 레이어에 소속 안 된 칸은 다른 레이어의 같은 열 범위를 보고 소속시키는 "orphan adoption" 단계 추가
- 플레이어 충돌을 발판 중심점 하나가 아니라 몸통 폭(±7px)까지 체크하도록 수정(모서리에서 그림과 겹쳐 보이던 문제)
- 맵 가장자리 바깥 칸(타일 데이터가 아예 없는 칸)이 "안 막힘"으로 잘못 판정되던 버그 수정 → 이제 맵 범위 밖은 무조건 막힘 처리. 실외 광장(plaza)에서 맵 밖으로 나가지던 문제, 집 안 맨 아래 가장자리에서 좌우로 빠져나가던 문제 둘 다 이걸로 해결
- 카메라 클램프가 스프라이트 크기를 고려 안 해서 맵 가장자리에서 캐릭터 머리가 잘려 보이던 문제 수정
- 레스토랑 울타리가 지붕 위로 올라오던 문제 → 원인은 세션 초반에 임시방편으로 Buildings 레이어를 "항상 뒤" 고정 그룹에 넣어뒀던 것; 몸통 폭 충돌 수정으로 그 임시방편이 불필요해져서 되돌리고 Y-sort 대상으로 복귀
- **집 안에서 문으로 들어가자마자 대각선으로 벽을 통과하는 것처럼 보이던 리포트**: 조사 결과 실제로는 버그가 아니라 문 안쪽 칸은 원래 뚫린 방바닥이라 정상 동작이었음(사용자도 확인 후 "그냥 둬도 된다"고 정리)
- **현재 미해결**: "타일 단위 추론"이라는 근본 구조 때문에 비슷한 버그가 계속 재발하는 패턴이 반복됨. 사용자가 "다른 2D 도트 게임들은 어떻게 처리하냐"고 물어서, 대부분의 게임은 타일이 아니라 "오브젝트 단위"(발밑 앵커 하나)로 정렬한다고 설명함. 다음 세션 방향으로 합의된 것: Tiled에 `YSortAnchor`라는 새 Object Layer를 만들어, 세로로 2칸 이상 차지하는 그림마다 그 물체 전체를 감싸는 사각형 오브젝트를 하나씩 그려 넣고, 코드는 그 사각형의 아랫변 y값을 그대로 정렬 기준으로 쓰도록 바꾸는 것(추론 로직 전부 걷어냄). **`home_map.gd`는 이 앵커 레이어를 읽도록 미리 코드 준비를 해뒀고, 실제 `Home.tmx`에 앵커 오브젝트를 그려 넣는 작업은 사용자가 다음 세션에 직접 진행하기로 함.** 이 항목은 다음 세션 최우선 확인 사항.
- (참고) "전체 리팩토링이 필요하냐"는 사용자 질문에는, 사용자가 "내 지시 전까지는 리팩토링하지 말아달라"고 명시했으므로 아직 답변/실행 보류 상태

### 7-7. 낮/밤 조명 시스템 신규 구현
