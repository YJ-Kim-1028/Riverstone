# Day 8 개발 현황 정리

`day7.md`에 이어지는 문서. 오늘은 세션이 길어서 다룬 범위가 넓다 - 농사 시스템 전체 구현(기획→코드→라이브 피드백 반영), 효과음 대량 연동, 상점/경제 기능 추가, 축산 미세조정, 레시피 아이템 버그 수정, 선물 주기 기능 완성, 그리고 마지막에 발견한 버그 2건(완성대 쥐약 아이콘, TAB 인벤토리 스크롤 부재)까지 처리했다. 문서 끝에는 오늘 코드를 다시 훑으며 새로 찾은, 지금까지 TO-DO에 없었던 미구현/버그 항목들을 별도로 정리했다(사용자 요청).

---

## 1. 오늘 완료한 것

### 1-1. 농사 시스템 전체 구현 (신규 - day7까지 "미착수"였던 항목)
- 신규 오토로드 `scripts/autoload/farming_manager.gd` + `data/crops/crops.json`(감자/옥수수/상추) 추가
- 괭이(`hoe`)로 밭 갈기 → 물뿌리개로 물주기 → 씨앗 심기 → 수확, 축산 시스템(`livestock_manager.gd`)과 동일한 "손에 든 도구로 칸과 상호작용" 패턴
- 라이브 플레이테스트 중 사용자 피드백을 받아 여러 차례 수정:
  - 상호작용 대상을 "바라보는 칸"이 아니라 "서있는 칸"으로 변경
  - 작물 그림이 그 자리에서 바로 안 바뀌고, 하루 자고 일어나야(다음날 아침) 성장이 반영되도록 변경
  - 다 자란 작물 + 물뿌리개를 동시에 들고 있을 때 수확이 물주기보다 우선하도록 순서 조정
  - 새싹 표시 기준을 "물 2번"에서 "물 1번"으로 낮춤
  - 감자/옥수수/상추 필요 급수 3/4/2 → 5/6/3으로 밸런스 재조정
  - 비 오는 날 자동 급수, 인벤토리 꽉 찼을 때 수확 프롬프트 자체를 숨기는 처리(낚시/축산과 동일 규칙 적용) 포함
- 괭이/물뿌리개는 상점 판매가 아니라 게임 시작부터 기본 소지, 인벤토리 `can_add_item()`/`is_full()` 헬퍼 신규 추가

### 1-2. 효과음(SFX) 대량 연동
- 괭이질/물주기/씨앗심기(파종은 조용히 처리)/수확, 소·돼지 여물주기, 우유·고기 획득, 구매(코인), 선물 전달, 추억의 물건 획득, 레시피 습득(아이템 소비 경로만 - 조합 발견 경로는 의도적으로 제외, [[project_recipe_learned_via_item]] 참고) 등 15종 이상 신규 연동
- 축산 실패 케이스(오늘 이미 여물 줌/이미 착유함 등) 전부 실패 비프(`SFX_BEEP`) 추가
- wav→mp3 전환 과정에서 깨져있던 경로 수정: `SFX_COIN`, `SFX_MIXER`, `SFX_RAIN`
- 자체 진단 스크립트로 전체 효과음 볼륨 측정 후, 사용자가 직접 귀로 확인한 결과에 따라 `footstep_interior`만 +5dB 조정(그 외엔 임의로 손대지 않음)
- 냄비 조리 중 보글보글 소리가 안 이어지던 문제(반복 재생 누락) 수정
- 연못/파도 등 기존 반복 재생 사운드와 동일한 루프 처리 규칙을 새 사운드에도 동일 적용

### 1-3. 상점 / 경제
- 인벤토리 슬롯 확장 구매 아이템 추가(동적 가격, 마르 잡화점) - 15→20→25칸, 최대 도달 시 "최대" 표시 + 버튼 비활성화
- 여물 등 손에 장착 중인 스택형 아이템을 구매하면 인벤토리 새 칸이 아니라 장착된 수량에 바로 합쳐지도록 수정(`EquipmentManager.top_up_equipped()` 신규)
- 기본 인벤토리 칸 수 10→15

### 1-4. 축산 미세조정
- 돼지 도살은 확인 팝업 없이 바로 처리(소는 유지) - `get_slaughter_request()`에 `needs_confirm` 추가
- 동물별 고기 획득량을 하드코딩(1개 고정) 대신 `animals.json`의 `meat_count`로 데이터화(소 3개/돼지 2개)

### 1-5. 레시피 관련 버그 3건 + 개선 1건
- **레시피 아이템을 아예 쓸 방법이 없던 버그** - 인벤토리 화면 "사용" 버튼이 `category == "consumable"`만 체크해서 `category == "recipe"` 아이템은 버튼 자체가 안 뜸. 조건 확장 + "배우기" 라벨 분기로 수정
- 조합으로 레시피를 처음 발견했을 때도 아이템 습득과 똑같은 효과음이 나던 버그 - `via_item` 플래그로 두 경로 분리, 조합 발견 쪽은 아직 전용 시각 효과가 없어서 효과음도 의도적으로 안 넣음(백로그, [[project_recipe_learned_via_item]])
- 도감(책장) 열자마자/페이지 넘기자마자 마우스가 이미 슬롯 위에 있으면 툴팁이 안 뜨던 버그 - 강제 hover 재판정으로 수정
- 도감 툴팁에 획득한 레시피의 재료 조합("찐 고등어 + 찐 고등어" 등)을 함께 표시하도록 개선

### 1-6. 조리대(Kitchen) UI
- 조리가 다 됐는데도 슬롯 아이콘이 원재료 그림 그대로 보이던 버그 - 완료 시 결과물 아이콘으로 바뀌도록 수정
- 조리시작 버튼 효과음이 너무 크다는 피드백으로 이 버튼 한정 볼륨 하향

### 1-7. 선물 주기 기능 완성
- 선물도 여물/도구와 동일하게 "손에 장착 후 NPC와 상호작용"으로 전달하도록 완성(`InventoryManager.give_gift_from_hand()`, `main.gd`의 프롬프트/입력 처리)
- 선물을 손에 들고 NPC에게 다가가면 "E 선물하기" 프롬프트, 오늘 이미 그 NPC에게 선물했으면 프롬프트 자체가 숨겨짐
- 사용자가 향수 선물로 직접 테스트 후 정상 동작 확인

### 1-8. 버그 수정 2건 (세션 막바지)
- **완성대(서빙 화면) 쥐약 아이콘** - 쥐약을 산 적 없어도 완성대에서 쥐약 토글 아이콘이 보이던 버그. `cooking_screen.gd`엔 있던 소지 여부 체크(`InventoryManager.has_item("rat_poison", 1)`)가 `serving_screen.gd`엔 빠져있었음 - 추가로 수정
- **TAB 상태창 "장비" 탭 인벤토리 스크롤 부재** - 예전 별도 인벤토리 화면(I키)을 장비 탭에 통합할 때, 그 화면엔 있던 `ScrollContainer`가 통합 과정에서 아예 빠진 채로 `GridContainer`만 남아있었음. 슬롯이 한 화면에 다 안 들어가면(인벤토리 확장 구매로 15칸 넘어가면) 그냥 잘려서 안 보이고 스크롤할 방법 자체가 없었음 - `inventory_screen.gd`와 동일한 `ScrollContainer` 구조/스크롤바 스타일을 `equipment_panel.tscn`/`.gd`에 추가해서 해결

### 1-9. 브레인스토밍만 하고 구현은 보류
- NPC 머리 위 이모지 반응 시스템: 7종 아이콘(웃음/하트/신남/물음표/불편/풀죽음/느낌표) + 트리거 매핑(마주침·헤어짐·추억의물건=웃음, 호감도 구간·좋아하는 음식=하트, 선물=신남 통일, 재회·새 이벤트=느낌표, 비 오는 날=풀죽음) 확정. 아트 없음, 코드 없음 - 순수 스펙만 확정된 상태([[project_npc_emote_backlog]])

## 3. 조사만 하고 미해결로 남긴 것

- **낚시 미니게임 클릭이 가끔 안 먹힌다는 리포트** - `fishing_manager.gd`의 물고기 노출 시간이 어종별 0.4~0.6초로 짧게 잡혀있음(`salmon`/`mackerel` 0.5초, `squid` 0.4초). 이 노출 시간 자체를 늘릴지는 아직 결정 안 됨 - 사용자가 "그냥 내가 늦은 걸 수도 있다"고 해서 우선 보류
- **셰퍼드(plaza3, 화요일) 상호작용 프롬프트가 안 뜨던 버그** - 그날 대화한 적이 없는데도(= `has_talked_today()` 때문이 아님) 근접 상호작용이 안 걸렸다는 리포트. 재현 조건을 특정 못 해서 사용자가 "일단 두자"고 보류. 재발하면 그날 셰퍼드 스케줄(맵/좌표)과 정확한 시간대를 같이 알려주면 원인 추적이 쉬움

## 4. 오늘 다시 코드를 훑다가 새로 찾은 것 (기존 TO-DO에 없던 항목)

사용자 요청으로 전체 스크립트/데이터에서 TODO·플레이스홀더·미완 신호를 다시 훑었다. 아래는 지금까지 어느 day 파일에도 명시적으로 적힌 적 없는 것들이다.

- **`recipe_random`(만능 요리 레시피, 마르 잡화점 1000골드, 구매 2회 한정) 아이템이 실제로 작동하지 않음** - `CookingManager._on_inventory_recipe_learned()`가 아이템 id에서 `"recipe_"` 접두사만 떼어 레시피 id로 쓰는데(`recipe_grilled_fish` → `grilled_fish`처럼 13종 정식 레시피는 이 규칙과 정확히 맞음), `recipe_random` → `"random"`이라는 레시피는 `data/cooking/recipes.json`에 아예 없음. 그래서 이 아이템을 사서 "사용"해도 `learn_recipe()`가 조용히 실패하고 아무 일도 안 일어남 - 돈만 쓰고 아무것도 못 배우는 상태. (의도가 "안 배운 레시피 중 무작위 하나"였을 것으로 추정되지만 그 로직 자체가 없음 - 구현 방향은 사용자 확인 필요, 지금은 손대지 않음)
- **레스토랑 이름을 입력하는 캐릭터 생성 화면이 아직 없음** - `mail_compose_panel.gd`가 초대장 발송 시 레스토랑 이름 자리에 `"우리 레스토랑"`이라는 고정값을 임시로 씀(주석에도 "그 화면이 생기면 실제 값으로 교체할 것"이라고 명시돼있음). 메인 화면(타이틀)이 아직 없는 것과 별개 항목
- **농사 시스템에 기획 문서가 없음** - 오늘 채팅으로 룰을 정하고 바로 코드로 구현했는데, `game_design/01_systems/`에 `farming.md`(또는 동급 문서)가 없어서 다른 시스템들과 달리 기획 문서-코드 짝이 안 맞는 상태. day7부터 이어지던 "기획 문서 추가 필요" 항목과 사실상 같은 건이지만, 이제는 코드가 기획보다 먼저 나가 있는 상태라는 점이 다름
- **공포 시스템(`MurderManager`/`HorrorEventManager`)의 신호는 있지만 실제 연출이 없는 부분이 예상보다 구체적으로 문서화돼있었음** (`data/horror/README.md` "아직 못 채운 것" 항목 재확인, day7의 "엔딩 연출 콘텐츠" 항목을 아래처럼 세분화):
  - 이메일함 UI, NPC 사망 시 초상화 회색 처리, 레스토랑 액자가 붉게 변하는 연출, 노크 소리 재생, 엔딩 컷신/크레딧 - 전부 로직(신호: `NPCManager.npc_died`, `HorrorEventManager.knock_event_triggered`/`impersonation_email_ready`, `MurderManager.truth_ending_triggered`/`arrest_ending_triggered`/`accomplice_ending_triggered`)까지만 있고 화면/오디오 표현이 없음
  - `data/horror/impersonation_emails.json` - 12명분 비어있음(플로라만 예시로 채워짐), 이건 day7에도 있던 항목과 동일
- **도감 전체 수집 보상**: `CollectionManager.full_memento_collection_achieved` 신호는 발생하지만 구독하는 곳이 코드 어디에도 없음(day1.md에 이미 "신호만 발생, 보상 없음"으로 기록돼있던 의도된 상태 - `collection.md` 원문에 "추후 결정"이라 명시됨). day7엔 `collection_reward()`라는 빈 함수가 있는 것처럼 적혀있었는데 실제로는 그런 함수 자체가 없고 그냥 아무도 안 듣는 신호만 있는 상태 - 표현을 정정
- **레시피 개별 아이템(만능 제외 13종)의 실제 획득 경로가 상점/낚시/이벤트 어디에도 없음** - `recipe_random` 말고는 상점에 등록된 레시피 아이템이 하나도 없어서, 지금은 사실상 "재료 조합을 직접 맞혀서 발견"하는 경로만 유효함. day7의 "레시피 실제 습득 경로" 항목과 같은 맥락이지만, 이번에 확인해보니 아이템 경로 자체는 (recipe_random 버그를 빼면) 코드적으로는 완성돼 있고 단지 그 아이템들을 얻을 데이터상의 통로가 없는 상태라는 게 명확해짐
